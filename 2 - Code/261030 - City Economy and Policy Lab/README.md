# 도시 경제와 정책 실험

세금 수입과 공공서비스 비용으로 월별 현금 / 부채를 계산하고, 네 가지 운영안의 서비스 성과와 재정 부담을 비교하는 Python 실습입니다.

**[skeleton/economy_rules.py](skeleton/economy_rules.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다. 함수별 입력과 반환값은 [작성 안내](skeleton/worksheet.md)에서 확인할 수 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 숫자와 딕셔너리로 소득 / 세금 / 비용을 표현하기
- 조건문과 반복문으로 세금, 운영비와 건설비 계산하기
- 월 수지와 차입 / 상환을 구분해 현금과 부채 갱신하기
- 입력을 보존하면서 계산 결과를 새 딕셔너리로 반환하기
- 같은 초기 조건에서 정책별 결과를 비교하고 설명하기

## 3. 재정 데이터를 읽는 방법

### 월별 재정과 단위

`session["finance"]`에는 현재 재정 상태가 저장됩니다. 제공 코드가 이 상태에서 필요한 값을 읽어 학생이 작성한 함수에 전달합니다. **규칙 함수에서는 전달받은 값으로 결과를 계산하고, 도시 상태를 직접 바꾸지 않습니다.**

| 값 | 기본값 | 의미 |
| --- | ---: | --- |
| `month` | 0 | 지난 개월 수. 재정의 1 tick은 1개월입니다. |
| `cash` / `debt` | 20 / 200 | 현재 보유 현금 / 남은 부채 |
| `reserve` | 20 | 결산 뒤에 남겨 둘 최소 보유 현금 |
| `interest_rate` | 0.01 | 월 이자율 1% |
| `employed` / `wage` | 200 / 5 | 취업자 수 / 1인당 월 임금 |
| `firm_profit` | 200 | 기업의 월 이익 합계 |
| `income_tax_rate` / `profit_tax_rate` | 0.1 / 0.1 | 가구 세율 / 기업 세율, 각각 10% |

금액은 학습용 **예산 단위**입니다. 함수에 전달하는 세율은 0~1 비율이며, 화면에서는 `%` 기호 없이 **10**처럼 퍼센트 숫자를 입력합니다. 기업 손실에 대한 세금은 0이고 손실 환급은 계산하지 않습니다. 수량과 단가는 음이 아닌 수로 주어집니다.

### 수입, 비용과 결산 규칙

기준 운영안의 월 세금 수입은 `200 × 5 × 0.1 + 200 × 0.1 = 120`입니다. 도로 8칸의 유지비 16과 시설 수선비 14를 더하면 유지관리비는 30이며, 서비스 운영비는 50입니다.

월 수지는 `세금 수입 - 유지비 - 운영비 - 이자 - 건설비`입니다. 이자는 **월초 부채**를 기준으로 계산합니다. **이번 달 신규 차입은 다음 달 이자에 반영합니다.**

차입과 원금 상환은 월 수지를 구한 뒤 처리합니다. `현금 + 월 수지 - 최소 보유 현금`이 음수이면 부족분을 빌리고, 양수이면 남은 부채 한도에서 상환합니다. 부채를 모두 갚고 남은 돈은 현금으로 보유합니다. 내부값은 반올림하지 않습니다.

### 같은 도시와 서로 다른 시계

- 도시 편집기는 일, 교통은 분, 공공서비스는 시간, 행위자와 재정은 각자의 월 단위를 사용합니다. 재정 1개월을 진행해도 다른 시계는 바뀌지 않습니다.
- 도로 유지비는 현재 지도에서 실제 도로 수를 읽습니다. 기존 도로 건설 버튼의 비용은 새 재정에 자동 청구하지 않습니다.
- 시민 3명의 행위자 예제, 서비스 집계 400명, 재정 계산의 취업자 200명은 구분합니다. 시민 3명을 단순히 확대해서 만든 값은 아닙니다.
- 고용, 임금, 기업 이익과 병원 요청은 고정된 가정입니다. 감세나 서비스 개선에 따른 고용 / 수요 증가는 자동으로 계산하지 않습니다.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/economy_rules.py`에서 해당 함수의 설명과 TODO 주석을 읽습니다.
2. 주석의 입력 / 반환값과 확인 예를 보고 코드를 작성합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 실행되지 않는 위치에 남겨 두어도 미구현 함수로 판단합니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다.

함수 이름 / 매개변수 / 반환 키를 유지하고, 입력 딕셔너리를 수정하지 마세요. TODO 3은 숫자 하나를, 나머지 함수는 새 딕셔너리를 반환합니다. 입력 검증 전체를 새로 작성할 필요는 없습니다.

| 단계 | 구현할 함수 | 이번 단계에서 할 일 | 검사 명령 |
| --- | --- | --- | --- |
| 1 | `tax_revenue` | 소득과 가구 / 기업 세금 계산 | `python skeleton/checks_economy.py --stage 1` |
| 2 | `monthly_costs` | 유지관리비와 서비스 운영비 집계 | `python skeleton/checks_economy.py --stage 2` |
| 3 | `construction_cost` | 공사 수량과 단가로 건설비 계산 | `python skeleton/checks_economy.py --stage 3` |
| 4 | `monthly_balance` | 이자와 차입 전 월 수지 계산 | `python skeleton/checks_economy.py --stage 4` |
| 5 | `settle_finances` | 차입 / 상환과 월말 현금 / 부채 계산 | `python skeleton/checks_economy.py --stage 5` |
| 6 | `compare_policy` | 지표별 비교안에서 기준을 뺀 변화량 계산 | `python skeleton/checks_economy.py --stage 6` |

`--stage 3`은 **1~3단계를 모두 검사**합니다. 단계를 생략한 `python skeleton/checks_economy.py`는 전체 6단계를 검사합니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[미구현] TODO 1: tax_revenue / economy_rules.py를 작성하세요.
1개 항목을 구현한 뒤 다시 확인하세요.
```

| 표시 | 의미와 다음 행동 |
| --- | --- |
| `[통과]` | 해당 검사에서 기대한 결과가 나왔습니다. |
| `[미구현]` | 필요한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]` | 계산 결과, 반환 형식이나 실행 중 예외를 확인해야 합니다. 함께 출력된 메시지를 읽으세요. |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 전체가 통과하면 `선택한 검사를 모두 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 `1`, 미구현 `2`입니다.

여섯 단계를 완성하면 월별 진행, 정책 비교, 저장 / 복원을 함께 검사하세요.

```sh
python skeleton/checks_economy.py --integration
```

`--integration`은 통합 검사만 실행하며 `--stage`와 함께 사용할 수 없습니다. TODO 1~3을 완성하면 월별 입력값을 확인할 수 있고, 1~5를 완성하면 재정을 진행할 수 있습니다. 정책 비교에는 TODO 6까지 필요합니다.

## 6. 결과를 비교해 보기

### 실험 A: 기준 운영안

1. 기본 지도를 수정하지 않은 상태에서 `기준`을 선택합니다.
2. 가구 세율과 기업 세율을 각각 `10`으로 입력하고 `적용 / 재정 초기화`를 누릅니다.
3. `1개월 진행`을 세 번 누르고 다음 표와 비교합니다.

| 시점 | 세금 수입 | 월 수지 | 월말 현금 | 부채 |
| --- | ---: | ---: | ---: | ---: |
| 0개월 | — | — | 20 | 200 |
| 1개월 | 120 | 38 | 20 | 162 |
| 2개월 | 120 | 38.38 | 20 | 123.62 |
| 3개월 | 120 | 38.7638 | 20 | 84.8562 |

첫 달 월 수지는 `120 - 30 - 50 - 200 × 0.01 = 38`입니다. 현금 20을 남겨 두고 38을 상환하므로 부채는 162가 됩니다. 화면에서는 소수 둘째 자리까지 표시하므로 3개월 말 부채는 84.86으로 보입니다.

### 실험 B: 동시 확충

운영안을 `동시 확충`으로 바꾸고 초기화한 뒤 두 달을 진행하세요.

| 시점 | 건설비 | 서비스 운영비 | 월 수지 | 신규 차입 | 월말 부채 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1개월 | 32 | 58 | -2 | 2 | 202 |
| 2개월 | 0 | 58 | 29.98 | 0 | 172.02 |

건설비는 첫 달에 한 번 지출하고 운영비는 매달 지출합니다. 둘째 달 이자가 2가 아니라 2.02인 이유를 설명해 보세요.

### 실험 C: 네 가지 운영안

두 세율이 10%로 적용되어 있는지 확인한 뒤 `정책 비교`에서 `네 가지 운영안 비교`를 누릅니다. 기본 지도를 수정하지 않았을 때의 결과입니다.

| 운영안 | 6시간 뒤 대기 인원 | 24시간 뒤 대기 인원 | 3개월 말 현금 | 3개월 말 부채 |
| --- | ---: | ---: | ---: | ---: |
| 기준 | 14 | 86 | 20 | 84.8562 |
| 병원 확충 | 3 | 57 | 20 | 123.4388 |
| 급수 확충 | 12 | 48 | 20 | 103.1576 |
| 동시 확충 | 0 | 0 | 20 | 141.7402 |

모든 운영안의 서비스 권역 인구는 300명으로 전체 400명의 75%입니다. D 지역의 시간당 요청 2명은 권역 밖 미배정 수요로 남습니다. **대기 인원이 0명이어도 모든 주민이 서비스를 받는 것은 아닙니다.**

6시간 뒤에는 병원 확충의 대기가 더 적지만 24시간 뒤에는 급수 확충의 대기가 더 적은 이유를 설명해 보세요. 대기 인원과 부채를 함께 고려하면 어떤 운영안을 선택하겠나요?

### 실험 D: 세율 변경

기준 운영안에서 가구 세율 `9`, 기업 세율 `10`을 적용하고 초기화한 뒤 3개월을 진행합니다. 세금 수입은 110, 세후 소득은 910, 3개월 말 부채는 115.1572입니다. 실험 A와 비교해 세금 수입과 부채가 어떻게 달라졌는지 설명해 보세요.

`세금과 행동`의 F1 기업 예제는 **만원** 단위이며 도시 예산과 합산하지 않습니다. 기업 세율 10%에서 6개월 세후 이전 순편익은 94만원, 30%에서는 -38만원입니다. 이 화면은 계산 예시를 보여 주며 기업 이전이나 고용 증가를 자동 실행하지 않습니다.

## 7. 막혔을 때 확인할 것

| 증상 | 확인할 내용 |
| --- | --- |
| `python` 명령을 찾지 못함 | Python 설치를 확인하고 환경에 맞게 `py` 또는 `python3`를 사용합니다. |
| `can't open file` 또는 파일을 찾지 못함 | 터미널이 이 README가 있는 폴더인지 확인합니다. 이미 `skeleton` 안이라면 `python app.py`, `python checks_economy.py --stage 1`처럼 폴더 접두사를 뺍니다. |
| Tkinter를 찾지 못하거나 창이 열리지 않음 | `python -m tkinter`로 설치를 확인합니다. GUI는 화면을 표시할 수 있는 PC에서 실행해야 합니다. 검사 스크립트는 GUI 없이 실행할 수 있습니다. |
| 코드를 썼는데 계속 미구현 | 저장 여부와 함수의 `raise NotImplementedError(...)` 줄을 확인합니다. 필요한 다른 함수가 미완성일 수도 있습니다. |
| 화면에 수정한 내용이 반영되지 않음 | 창을 닫고 다시 실행합니다. `solution` 대신 `skeleton`을 실행했는지도 확인합니다. |
| 세율이나 운영안을 바꿨는데 결과가 같음 | `적용 / 재정 초기화`를 눌렀는지 확인합니다. 비교 표는 `네 가지 운영안 비교`를 다시 눌러 갱신합니다. |
| `KeyError` 또는 반환 형식 오류 | 작성 안내의 키 철자와 반환 자료형을 확인합니다. 입력 딕셔너리는 변경하지 않습니다. |
| 세금이 너무 크거나 세율 오류 발생 | 화면의 10% 입력은 `10`, 함수에 전달하는 비율은 `0.1`입니다. |
| 첫 달은 맞지만 이후 부채가 다름 | 월초 부채로 이자를 계산했는지, 건설비를 첫 달에만 반영했는지, 내부값을 반올림하지 않았는지 확인합니다. |
| 부채보다 많이 상환하거나 현금이 사라짐 | 상환액을 남은 부채 이하로 제한하고, 상환 뒤 남는 돈을 현금에 포함했는지 확인합니다. |
