## 진행

- 도입 / 실행 준비 / 도시 구조 9분: 슬라이드 1~7.
- 여섯 규칙의 예제 / 작성 / 검사 / 해설 60.5분: 슬라이드 8~38. 직접 작성은 각 5분씩 총 30분이다.
- 통합 / 조건 비교 / 기록과 복원 19분: 슬라이드 39~49.
- 정리 1.5분: 슬라이드 50~51.

한 학생의 화면 오류 때문에 전체 실습이 멈추지 않도록 우선 `python checks_services.py --stage N`으로 1단계부터 N단계까지 순수 함수를 누적 검사한다. 여섯 함수를 모두 완성하면 `python checks_services.py`와 `python checks_services.py --integration`을 차례로 실행한 뒤 GUI를 진행한다. 코드 수정 후 앱을 재실행해야 새 함수를 읽는다. 함수를 대신 수행하는 숨은 정답 코드는 스켈레톤에 없다.

## 결과 해석

기본 1시간은 권역 75% / 대기 2명 / 물 저장 8 m³ / 오염 [72, 18, 0]이다. 기본 6시간째 대기가 12명이 아니라 14명인 이유는 저장된 물이 고갈되어 실제 공급이 6 m³, 병원 처리 능력이 6명으로 줄기 때문이다.

정전 2~3시간째 병원은 60 kWh 비상전원을 30 kW로 사용한다. 첫 정전 구간에는 물탱크의 8 m³로 급수와 진료가 가능하다. 다음 정전 구간에는 병원 전력은 있지만 물이 없어 진료 능력이 0이 된다. 제공 모형은 그 구간에도 필수 장비 전력 30 kW를 사용한다고 가정한다.

침수 때 D는 애초 권역 밖이었으므로 권역 비율은 여전히 75%이다. 그러나 이동시간 20분과 경로 없음은 서로 다르며, 경로가 없는 인구가 100명으로 늘어난다. 비율 하나만 볼 때 놓치는 정보다.

학교와 소방은 서로 다른 용량의 의미를 확인하는 제공 예제다. 학교 배정은 장기 점유, 소방은 차량의 출동과 복귀, 병원은 구간 처리 능력을 다룬다. 이번에 학생이 세 종류의 배정 알고리즘을 모두 새로 작성하게 하지 않는다.

## 평가에 활용할 확인 기준

1. 여섯 함수가 입력을 수정하지 않고 명세에 맞는 반환값을 만드는가?
2. 진료 / 물 / 폐기물의 유입, 유출, 잔량이 맞는가?
3. 같은 초기 조건에서 대안을 비교했는가?
4. 개선된 지표와 남은 문제를 함께 설명하는가?
5. 서비스 집계 400명과 기존 행위자 3명을 혼동하지 않는가?

점수와 제출 일정은 별도 수업 공지에서 정한다. GUI는 실제 디스플레이가 가능한 강의실 PC에서 `python app.py --smoke`로 확인한다.
