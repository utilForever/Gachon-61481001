# 도로망과 교통 실습

5×4 격자의 도로를 그래프로 바꾸고, 이동 경로 / 교통 혼잡 / 일자리 접근성을 계산하는 Python 실습입니다.

**[skeleton/traffic.py](skeleton/traffic.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 딕셔너리와 리스트로 도로와 이웃 정보를 표현하기
- 연결 요소를 찾아 서로 이동할 수 있는 도로 구역을 구분하기
- BFS의 최소 구간 경로와 Dijkstra / A\*의 최소 시간 경로를 비교하기
- 유입량과 처리 용량으로 1분 뒤의 대기열 계산하기
- 시간 한도 안에 도달할 수 있는 일자리 수를 구하고 예상 결과와 비교하기

## 3. 도로와 교통 데이터를 읽는 방법

### 좌표와 도로 그래프

- 지도는 가로 5칸, 세로 4칸입니다. `x`는 0~4, `y`는 0~3입니다.
- 좌표는 `(x, y)`로 표현하며, 셀은 **`city["grid"][y][x]`** 순서로 읽습니다.
- `cell["road"]`가 `True`인 셀만 노드입니다. 건물과 빈 땅은 경로에 포함하지 않습니다.
- 상하좌우로 맞닿은 도로끼리 연결합니다. 대각선 이동은 허용하지 않습니다.
- 도로 연결은 양방향이며, 이웃이 없는 도로도 하나의 노드입니다.

그래프는 `{좌표: 이웃 좌표 리스트}` 형태입니다. 기본 도시의 일부는 다음과 같습니다.

```python
{
    (2, 0): [],
    (0, 2): [(1, 2), (0, 3)],
    (1, 2): [(0, 2), (2, 2), (1, 3)],
}
```

위 예시는 전체 그래프가 아닙니다. `(2, 0)`은 고립된 도로이고, `(0, 2)`에서는 `(1, 2)`와 `(0, 3)`으로 이동할 수 있습니다.

### 거리와 이동시간

| 값                          | 의미                                              |
| --------------------------- | ------------------------------------------------- |
| `travel_times[node]`        | 해당 도로 셀에 진입하는 데 걸리는 시간, 단위는 분 |
| `state["base_times"][node]` | 대기열이 없을 때의 기본 진입 시간                 |
| `state["queues"][node]`     | 해당 도로의 현재 대기 차량 수, 단위는 대          |
| `state["capacities"][node]` | 해당 도로의 분당 처리 용량, 단위는 대/분          |
| `state["arrivals"]`         | 선택한 도로에 매분 들어오는 차량 수, 단위는 대/분 |
| `state["minute"]`           | 대기열 실험에서 진행한 시간, 단위는 분            |

한 구간의 기본 거리는 100 m입니다. 경로의 이동거리는 **노드 수가 아닌 간선 수**에 비례합니다. 노드 4개를 거치는 경로라면 이동한 구간은 3개입니다.

예상 진입 시간은 `기본 진입 시간 + 현재 대기 차량 수 / 분당 처리 용량`입니다. 예를 들어 기본 1분, 대기 20대, 처리 용량 5대/분이면 5분입니다. 이 계산은 `traffic_data.cost_snapshot()`에서 제공됩니다.

**경로의 총시간에는 출발 셀의 진입 시간을 더하지 않습니다.** 이미 출발 셀에 있다고 가정하고, 다음 셀부터 도착 셀까지의 시간을 합합니다.

| 알고리즘 | 최소화하는 값 | 이번 실습에서의 역할                                                 |
| -------- | ------------- | -------------------------------------------------------------------- |
| BFS      | 이동 구간 수  | TODO 3에서 구현합니다. 각 셀의 혼잡 시간은 탐색에 사용하지 않습니다. |
| Dijkstra | 총 이동시간   | 제공 코드로 실행하고 BFS와 비교합니다.                               |
| A\*      | 총 이동시간   | 제공된 휴리스틱 탐색으로 실행하고 결과를 비교합니다.                 |

### 대기열과 일자리

대기열은 기존 대기 차량에 이번 분의 유입을 더한 뒤, 처리 용량까지 차량을 내보내는 모델입니다. **처리한 차량 수 + 남은 대기 차량 수 = 기존 대기 + 유입**이어야 하며, 대기 차량 수는 음수가 될 수 없습니다.

일자리는 운영 중인 상점 / 공장의 **전체 수용량 `capacity`**을 사용합니다. 현재 점유 일자리 수인 `workers`와 구분하세요. 제공 함수 `job_destinations()`가 각 건물을 `{"id": ..., "entrances": [...], "jobs": ...}` 형태로 준비합니다.

건물에 인접한 도로 중 하나라도 시간 한도 **이내**에 도달하면 해당 건물의 일자리를 더합니다. 입구가 여러 개이거나 같은 건물 ID가 반복되어도 한 번만 셉니다. 접근성 계산에서는 출발지에서 모든 도로까지의 최소 시간을 사용하며, 화면에서 선택한 도착 도로 T로 대상을 제한하지 않습니다.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/traffic.py`에서 해당 함수와 TODO 주석을 읽습니다.
2. `pass` 자리에 코드를 작성합니다. 주석만 있는 TODO는 그 아래에 코드를 추가합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 아래 코드는 실행되지 않습니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. TODO 3은 A~C, TODO 6은 A~B를 함께 완성합니다.

| 단계 | 구현할 함수             | 이번 단계에서 할 일                                  | 검사 명령                             |
| ---- | ----------------------- | ---------------------------------------------------- | ------------------------------------- |
| 1    | `build_road_graph`      | 도로 좌표와 상하좌우 이웃 목록을 dict로 반환         | `python skeleton/checks.py --stage 1` |
| 2    | `connected_components`  | 노드별 연결 요소 번호를 0번부터 기록                 | `python skeleton/checks.py --stage 2` |
| 3    | `bfs_path`              | 최소 구간 경로를 리스트로 반환하고 도달 불가 처리    | `python skeleton/checks.py --stage 3` |
| 4    | `route_metrics`         | 간선 수로 거리를 구하고 출발 셀을 제외한 시간을 합산 | `python skeleton/checks.py --stage 4` |
| 5    | `advance_queue`         | 처리 차량 수와 1분 뒤 대기 차량 수를 dict로 반환     | `python skeleton/checks.py --stage 5` |
| 6    | `count_accessible_jobs` | 시간 한도 안의 일자리를 건물 ID마다 한 번만 합산     | `python skeleton/checks.py --stage 6` |

`--stage 3`은 **1~3단계를 모두 검사**합니다. 제공 코드 검사는 항상 먼저 실행하며, 6단계까지 선택하면 통합 검사도 실행합니다. 옵션을 생략한 `python skeleton/checks.py`는 `--stage 6`과 같습니다. 앞 단계에서 실패했다면 해당 단계부터 확인하세요.

검사 코드는 이전 실습처럼 일반 함수 `check_stage_1`~`check_stage_6`으로 구성되어 있습니다. `STAGES`는 단계 설명과 검사 함수를 묶은 목록입니다. 각 단계에서는 정상 입력, 경계 조건, 입력 보존 등 여러 조건을 확인합니다.

`neighbors4`와 `routing.py`의 Dijkstra / A\* 함수는 제공된 함수를 그대로 사용합니다. 함수 이름과 매개변수, 반환 형식도 유지해야 화면과 검사 코드가 여러분의 함수를 호출할 수 있습니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[통과] 제공 코드
[미완성] TODO 1: 도로 그래프: TODO 1: 도로 그래프를 만드세요.
```

| 표시       | 의미와 다음 행동                                                             |
| ---------- | ---------------------------------------------------------------------------- |
| `[통과]`   | 해당 검사에서 기대한 결과가 나왔습니다.                                      |
| `[미완성]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]`   | 기대한 결과와 실제 결과가 다릅니다. 함께 출력된 두 값을 비교하세요.          |
| `[오류]`   | 실행 중 예외가 발생했습니다. 오류 메시지와 파일 / 줄 번호를 확인하세요.      |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 요청한 검사를 모두 통과하면 `요청한 모든 점검을 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, 미완성 `2`입니다. 실패와 미완성이 함께 있으면 `1`을 반환합니다. 검사는 GUI 없이 실행할 수 있습니다.

도로 노드는 행 / 열 순서로 등록하고, 이웃은 `neighbors4`의 왼쪽 / 오른쪽 / 위 / 아래 순서를 유지하세요. BFS의 이전 노드와 연결 요소 번호는 **큐에 넣을 때 기록**해야 같은 노드를 중복해서 넣지 않습니다.

이 파일의 함수는 입력을 읽기만 합니다. 경로가 없을 때와 노드가 하나뿐일 때를 구분하고, 결과는 새 dict나 list, 숫자 또는 `None`으로 반환하세요. 정확한 반환 키와 확인 예는 각 함수의 설명과 TODO 주석을 참고합니다.

교통 상태를 바꾸면 계산한 경로와 접근성 결과가 초기화됩니다. `도로망 분석`, `경로 비교`, 접근성의 `계산`을 다시 실행해 바뀐 상태를 확인하세요. `대기열 초기화`는 혼잡 시나리오의 초기 대기 20대를 복원하는 버튼이 아닙니다. 초기 혼잡 상태로 돌아가려면 `혼잡 도시`를 다시 선택합니다.

도시 편집기의 지도 편집은 도시 시간이 0일일 때 가능합니다. 편집기에서 `1일 진행`을 눌렀다면 `실험 시작으로`를 눌러 0일 상태로 돌아간 뒤 편집하세요. **도시의 날짜 `day`와 교통의 시간 `minute`은 별개**이며, 교통의 `1분 진행`은 도시 날짜를 늘리지 않습니다.

다음 파일도 `불러오기`로 열 수 있습니다. 이전 실습의 도시 전용 JSON과는 형식이 다릅니다.

- [혼잡 도시](skeleton/examples/traffic_congested.json)

## 6. 결과를 비교해 보기

### 실험 A: 기본 / 혼잡 / 단절 도시 비교

각 시나리오를 새로 선택하고, **출발 `(0, 2)`, 도착 `(3, 2)`, 접근성 한도 4분**을 유지한 채 분석하세요. 아래 표는 대기열을 진행하거나 지도를 편집하기 전의 결과입니다.

| 시나리오 | 도로 노드 / 연결 구간 / 연결 요소 | BFS 거리 / 시간 | Dijkstra / A\* 거리 / 시간 | 4분 이내 일자리 |
| -------- | --------------------------------- | --------------- | -------------------------- | --------------- |
| 기본     | 9 / 10 / 2                        | 300 m / 3분     | 300 m / 3분                | 32개            |
| 혼잡     | 9 / 10 / 2                        | 300 m / 7분     | 500 m / 5분                | 20개            |
| 단절     | 7 / 5 / 3                         | 경로 없음       | 경로 없음                  | 0개             |

연결 구간은 양방향 연결을 한 구간으로 셉니다. 기본 도시에도 고립된 도로 `(2, 0)`이 있어 연결 요소는 2개입니다.

혼잡 도시는 `(1, 2)`에 대기 차량 20대가 있어 그 셀의 진입 시간이 5분입니다. BFS는 구간 수가 적은 길을 택하고, Dijkstra와 A\*는 혼잡한 셀을 우회합니다. 상점 J의 일자리는 12개, 공장 F의 일자리는 20개이며, 혼잡 시나리오에서는 4분 이내에 공장 F만 도달할 수 있습니다.

다음을 설명해 보세요.

1. 혼잡 도시에서 더 먼 경로가 더 빠른 이유는 무엇인가요?
2. 기본 도시의 연결 요소가 2개여도 S에서 T로 이동할 수 있는 이유는 무엇인가요?
3. 도로를 끊으면 거리뿐 아니라 일자리 접근성도 달라지는 이유는 무엇인가요?

### 실험 B: 대기열 증가와 해소

1. `기본 도시`를 선택합니다. 관찰 도로는 `(1, 2)`입니다.
2. 유입 8대/분, 처리 용량 5대/분, 대기 0대인지 확인합니다.
3. `1분 진행`을 네 번 눌러 기록을 비교합니다.

| 경과 시간 | 이번 분 처리 | 남은 대기 |
| --------- | ------------ | --------- |
| 1분       | 5대          | 3대       |
| 2분       | 5대          | 6대       |
| 3분       | 5대          | 9대       |
| 4분       | 5대          | 12대      |

유입을 0으로 바꾸고 `값 적용`을 누른 뒤 세 번 더 진행하면 대기는 **7대 → 2대 → 0대**가 됩니다. 마지막 분에는 2대만 처리됩니다. 대기 차량이 늘거나 줄 때 `경로 비교`를 다시 실행해 예상 이동시간도 확인하세요.

이 모델은 선택한 도로의 대기열을 갱신하고 현재 상태로 예상 시간을 계산합니다. 차량 하나하나가 도로망 전체를 이동하거나, 이동 도중 혼잡이 바뀌는 과정까지 시뮬레이션하지는 않습니다.

| 증상                                        | 확인할 내용                                                                                                                  |

| `python` 명령이나 파일을 찾지 못함          | Python 설치와 현재 폴더를 확인하세요. 이미 `skeleton` 안이라면 `python app.py`, `python checks.py --stage 1`처럼 실행합니다. |

| 작성했는데도 `NotImplementedError`가 발생함 | 파일 저장 여부, 실행한 폴더, 해당 함수에 남아 있는 `raise NotImplementedError(...)`를 확인하세요.                            |
| `--task`를 인식하지 못함                    | 이전 실습과 같은 `--stage 1`부터 `--stage 6`까지 사용합니다. 전체 검사는 옵션을 생략합니다.                                  |
| 노드나 이웃의 순서가 다름                   | 행 / 열 순회와 `neighbors4`의 순서를 지키세요. 순서를 잃는 집합으로 이웃 리스트를 만들지 않았는지 확인합니다.                |
| BFS가 끝나지 않거나 경로가 반복됨           | 큐에 넣을 때 방문 여부를 기록하고, 이미 발견한 노드를 다시 넣지 않았는지 확인하세요.                                         |
| 경로의 거리가 100 m 더 길게 나옴            | 노드 수 대신 간선 수로 거리를 계산했는지 확인하세요.                                                                         |
| 경로의 시간이 예상보다 큼                   | 출발 셀의 진입 시간까지 더하지 않았는지 확인하세요.                                                                          |
| 대기 차량이 음수가 됨                       | 실제로 처리 가능한 차량 수를 제한했는지 확인하세요.                                                                          |
