# 가상 도시 모델링 실습

5×4 격자에 주택 / 공원 / 도로를 배치하고, 하루가 지날 때 인구와 예산이 어떻게 바뀌는지 구현하는 Python 실습입니다.

**[skeleton/model.py](skeleton/model.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 리스트와 딕셔너리로 지도와 건물 정보를 표현하기
- 조건문과 반복문으로 주변 환경을 확인하기
- 작은 함수를 조합해 입주 조건과 인구 변화를 계산하기
- 하루 시작 상태를 보존하면서 다음 날 상태 만들기
- 예상 결과와 실제 결과를 비교하며 구현 확인하기

| 폴더                  | 용도                                                              |
| --------------------- | ----------------------------------------------------------------- |
| [skeleton](skeleton/) | 학생용 코드입니다. `model.py`에 구현할 부분이 남아 있습니다.      |
| [solution](solution/) | 모범 답안입니다. 직접 구현한 뒤 동작과 풀이를 비교할 수 있습니다. |

두 폴더는 각각 독립적으로 실행할 수 있으며, 다음 파일을 포함합니다.

| 파일           | 역할                                                      |
| -------------- | --------------------------------------------------------- |
| `app.py`       | 프로그램을 실행하는 시작점                                |
| `model.py`     | 이웃 탐색, 인구 계산, 건물 배치, 하루 갱신 등 도시 규칙   |
| `city_data.py` | 도시 초기화, 데이터 검증, 도로 편집, JSON 저장 / 불러오기 |
| `gui.py`       | 지도와 버튼을 표시하는 화면                               |
| `checks.py`    | TODO별 누적 검사                                          |
| `examples/`    | 기본 도시, 공원 없는 도시, 빈 지도의 JSON 예제            |

실습에서는 `skeleton/model.py`를 수정합니다. 다른 파일은 실행과 검사를 도와주는 제공 코드입니다.

## 3. 도시 데이터를 읽는 방법

### 좌표와 건물

- 지도는 가로 5칸, 세로 4칸입니다. `x`는 0~4, `y`는 0~3입니다.
- 좌표는 `(x, y)`로 표현하지만, 셀을 읽을 때는 **`city["grid"][y][x]`** 순서입니다.
- 각 셀에는 지형 `terrain`, 도로 유무 `road`, 건물 ID `building_id`가 있습니다.
- `city["buildings"]`는 건물 ID를 키로, 건물 정보 딕셔너리를 값으로 저장합니다.

예를 들어 기본 도시의 `(2, 1)` 셀을 읽으면 `building_id`가 `"P"`입니다. 실제 공원 정보는 `city["buildings"]["P"]`에서 찾습니다. **셀에 저장하는 것은 건물 정보 전체가 아니라 ID입니다.**

| 값                    | 의미                                                                        |
| --------------------- | --------------------------------------------------------------------------- |
| `city["day"]`         | 지난 날짜. 처음은 0일이며, 1 tick은 1일입니다.                              |
| `city["budget"]`      | 도시 예산, 단위는 코인                                                      |
| `building["kind"]`    | `"house"`는 주택, `"park"`는 공원                                           |
| `building["status"]`  | `"construction"`은 건설 중, `"operating"`은 운영 중, `"closed"`는 운영 중지 |
| `house["population"]` | 해당 주택에 현재 거주하는 인구                                              |
| `house["capacity"]`   | 해당 주택이 수용할 수 있는 최대 인구                                        |

### 입주와 예산 규칙

다음 조건을 모두 만족하는 주택에 사람이 입주할 수 있습니다.

1. 주택이 운영 중입니다.
2. 도시의 외부 전력이 켜져 있습니다.
3. 상하좌우 이웃에 도로가 하나 이상 있습니다.
4. 공원 반경 안에 운영 중인 공원이 하나 이상 있습니다.

공원까지의 거리는 **가로 차이의 절댓값 + 세로 차이의 절댓값**으로 계산합니다. 예를 들어 `(1, 1)`에서 `(2, 2)`까지는 2칸입니다. 반경과 같은 거리도 포함하며, 도로는 대각선 이웃을 세지 않습니다.

| 규칙                  | 기본값 | 의미                                              |
| --------------------- | -----: | ------------------------------------------------- |
| `growth_per_day`      |      2 | 조건을 만족하는 주택 한 채에 하루 최대 2명 입주   |
| `tax_per_person_day`  |      3 | 하루 시작 인구 1명당 세금 3코인                   |
| `maintenance_per_day` |     10 | 도시 전체에서 하루에 한 번 차감하는 유지비 10코인 |
| `park_radius`         |      1 | 주택에서 공원까지 허용하는 거리                   |

입주량은 주택의 빈자리를 초과할 수 없습니다. 빈자리가 1명이면 하루 최대 입주량이 2여도 1명만 들어옵니다.

하루 뒤 예산은 `시작 예산 + 시작 총인구 × 1인당 세금 - 하루 유지비`입니다. **오늘 새로 입주한 사람은 오늘 세금 계산에 포함하지 않습니다.** 코드에서는 숫자를 고정해서 쓰지 말고 `city["rules"]`의 값을 읽으세요.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/model.py`에서 해당 함수와 TODO 주석을 읽습니다.
2. `pass` 자리에 코드를 작성합니다. 주석만 있는 TODO는 그 아래에 코드를 추가합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 아래 코드는 실행되지 않습니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. TODO 3, 4, 6은 여러 부분으로 나뉘어 있으므로 각 부분을 함께 완성합니다.

| 단계 | 구현할 함수        | 이번 단계에서 할 일                                      | 검사 명령                             |
| ---- | ------------------ | -------------------------------------------------------- | ------------------------------------- |
| 1    | `neighbors4`       | 지도 안의 상하좌우 좌표를 리스트로 반환                  | `python skeleton/checks.py --stage 1` |
| 2    | `total_population` | 모든 주택의 인구 합계를 반환                             | `python skeleton/checks.py --stage 2` |
| 3    | `place_building`   | 배치 가능 여부를 확인하고 건물 / 셀에 정보를 연결해 저장 | `python skeleton/checks.py --stage 3` |
| 4    | `eligible`         | 운영 상태 / 전력 / 도로 / 공원으로 입주 조건을 판단      | `python skeleton/checks.py --stage 4` |
| 5    | `arrivals`         | 입주 조건과 빈자리에 맞는 하루 입주량을 반환             | `python skeleton/checks.py --stage 5` |
| 6    | `step`             | 인구 / 예산 / 날짜를 갱신한 새 도시를 반환               | `python skeleton/checks.py --stage 6` |

`--stage 3`은 **1~3단계를 모두 검사**합니다. 뒤 단계에서 앞 단계 함수를 사용하므로 앞 단계의 실패부터 해결하세요. 단계를 생략한 `python skeleton/checks.py`는 전체 6단계를 검사합니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[통과] 제공 코드
[미완성] TODO 1: 이웃 셀: TODO 1: 이웃 셀을 구하세요.
```

| 표시       | 의미와 다음 행동                                                             |
| ---------- | ---------------------------------------------------------------------------- |
| `[통과]`   | 해당 검사에서 기대한 결과가 나왔습니다.                                      |
| `[미완성]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]`   | 기대값과 실제 값이 다릅니다. 함께 출력된 두 값을 비교하세요.                 |
| `[오류]`   | 실행 중 예외가 발생했습니다. 오류 메시지와 파일 / 줄 번호를 확인하세요.      |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 전체가 통과하면 `요청한 모든 점검을 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, 미완성 `2`입니다.

| 도구 / 버튼                          | 사용 방법                                                                |

| 도로                                 | 비어 있는 땅에 도로를 설치합니다. 같은 도로를 다시 클릭하면 삭제합니다.  |

| 외부 전력                            | 도시의 전력 공급을 켜거나 끕니다.                                        |
| 1일 진행                             | 하루 뒤 인구와 예산을 계산하고 실행 기록에 표시합니다.                   |
| 실험 시작으로                        | 처음 `1일 진행`을 누르기 직전의 상태로 돌아갑니다.                       |
| 저장 / 불러오기                      | 현재 도시 상태를 JSON 파일로 저장하거나 불러옵니다.                      |

**지도 편집과 외부 전력 변경은 0일에만 가능합니다.** 하루를 진행하면 편집 도구가 잠깁니다. 다시 편집하려면 0일의 시작 상태로 돌아가거나 시나리오를 새로 선택하세요. 1일 이후의 JSON을 불러온 경우에는 `실험 시작으로`를 눌러도 그 파일의 시작 날짜로 돌아갑니다.

`불러오기`에서 [기본 도시](skeleton/examples/default.json), [공원 없는 도시](skeleton/examples/no_park.json), [빈 지도](skeleton/examples/empty.json) 예제도 선택할 수 있습니다.

## 6. 결과를 비교해 보기

### 실험 A: 기본 도시

1. `기본 도시`를 선택합니다. A 주택은 6명, B 주택은 8명이며 수용량은 각각 10명입니다.
2. 지도를 수정하지 않고 `1일 진행`을 두 번 누릅니다.
3. 다음 표와 실행 기록을 비교합니다.

| 날짜 | A 인구 | B 인구 | 전체 인구 | 예산 |
| ---- | -----: | -----: | --------: | ---: |
| 0일  |      6 |      8 |        14 |  100 |
| 1일  |      8 |     10 |        18 |  132 |
| 2일  |     10 |     10 |        20 |  176 |

1일 예산은 `100 + 14 × 3 - 10 = 132`, 2일 예산은 `132 + 18 × 3 - 10 = 176`입니다.

### 실험 B: 공원 없는 도시

`공원 없는 도시`를 선택하고, 지도를 수정하지 않은 상태에서 이틀을 진행하세요.

| 날짜 | 전체 인구 | 예산 |
| ---- | --------: | ---: |
| 0일  |        14 |  100 |
| 1일  |        14 |  132 |
| 2일  |        14 |  164 |

공원이 없어 새 입주자는 없지만, 기존 주민의 세금은 계속 계산합니다. 두 도시의 1일 예산은 같고 2일 예산부터 달라지는 이유를 설명해 보세요.

추가로 기본 도시에서 **0일에** 외부 전력을 끄거나 A 주택 바로 아래 `(1, 2)`의 도로를 삭제한 뒤, 어느 주택에 사람이 입주하는지 예상하고 확인해 보세요.

| 코드를 썼는데 계속 미완성                | 저장 여부와 해당 함수의 `raise NotImplementedError(...)` 줄을 확인합니다. 앞 단계 함수에서 발생한 미완성일 수도 있습니다.                       |

| 인구는 맞는데 예산이 다름                | 세금을 하루 시작 총인구로 계산했는지, 유지비를 하루에 한 번 차감했는지 확인합니다.                                                              |
| 이전 날짜의 도시까지 바뀜                | `step`에서 `old`나 `house`를 수정하지 않았는지, `deepcopy`로 독립적인 상태를 만들었는지 확인합니다.                                             |
