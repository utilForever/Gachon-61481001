# 반복 실험, 검증과 최종 통합 실습

병원에 시간별로 방문하는 인원을 만들고, 진료 용량을 바꿨을 때 마지막에 기다리는 인원이 어떻게 달라지는지 비교하는 Python 실습입니다. 같은 입력으로 반복 실행하고, 결과 검사와 저장 / 재현까지 확인합니다.

**[skeleton/validation_rules.py](skeleton/validation_rules.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트와 확인 예시는 코드 바로 옆 주석에 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 계산 결과가 주어진 규칙에 맞는지 조건문으로 검사하기
- 시드로 방문 목록을 만들고 같은 입력을 다시 생성하기
- 이전 실행의 상태를 남기지 않고 한 회차를 독립적으로 실행하기
- 평균 / 표본 표준편차 / 범위를 함께 보고 결과 비교하기
- 같은 입력으로 여러 용량을 비교하고 저장된 기록 재현하기

| 폴더                  | 용도                                                                    |
| --------------------- | ----------------------------------------------------------------------- |

두 폴더는 각각 독립적으로 실행할 수 있으며, 이번 실습의 주요 파일은 다음과 같습니다.

## 3. 실험 데이터를 읽는 방법

### 입력과 시간별 기록

- `arrivals`는 시간별 방문 인원 리스트입니다. `[9, 14, 11]`이면 첫 시간에 9명, 다음 시간에 14명, 그다음 시간에 11명이 방문합니다.
- `capacity`는 한 시간에 진료할 수 있는 인원입니다. 한 회차 안에서는 같은 용량을 사용합니다.
- `queue`는 이번 시간이 시작할 때 기다리던 인원입니다. **한 회차를 시작할 때마다 0명으로 초기화합니다.**
- 제공된 `advance_queue(queue, visitors, capacity)`의 결과에서 `served`는 진료 인원, `queue`는 그 시간 끝의 대기 인원입니다.

진료 인원은 `min(기존 대기 + 새 방문, 진료 용량)`, 남은 대기는 `기존 대기 + 새 방문 - 진료 인원`입니다. 결과를 검사할 때는 인원의 합뿐 아니라 **가능한 인원만큼 진료했는지**도 확인하세요.

| 값                       | 의미                                                      |
| ------------------------ | --------------------------------------------------------- |
| `history`                | 1시간째부터 차례로 저장한 기록 리스트                     |
| `history[0]["hour"]`     | 첫 기록의 시각. 값은 1이며, 리스트 인덱스 0과 구분합니다. |
| `history[0]["arrivals"]` | 첫 시간에 새로 온 인원                                    |
| `history[0]["served"]`   | 첫 시간에 진료한 인원                                     |
| `history[0]["queue"]`    | 첫 시간이 끝난 뒤 남은 대기 인원                          |
| `final_queue`            | 한 회차가 끝난 뒤 남은 대기 인원                          |

시간별 기록은 매번 새 dict로 만듭니다. 같은 dict를 고쳐 가며 리스트에 넣으면 이전 기록까지 함께 바뀔 수 있습니다. 빈 방문 목록의 실행 결과는 빈 `history`와 `final_queue` 0입니다.

### 비교와 요약 규칙

| 조건                  | 기본값                                               |
| --------------------- | ---------------------------------------------------- |
| 시간 단위 / 실행 기간 | 1시간 / 6시간                                        |
| 시간별 방문 인원      | 6~14명 중 독립적으로 추출하며, 각 정수의 확률은 같음 |
| 기준 / 비교 진료 용량 | 8명/시간 / 10명/시간                                 |
| 반복 횟수 / 시드      | 30회 / 101~130                                       |
| 용량별 비교 대상      | 6 / 8 / 10 / 12 / 14명/시간                          |
| 비교 지표             | 각 회차의 6시간 후 대기 인원                         |

한 시드로 방문 목록을 한 번 만들고 두 용량에 공통으로 사용합니다. 서로 다른 방문 목록을 주면 용량 차이와 입력 차이가 함께 섞입니다. **기준 실행의 마지막 대기를 비교 실행의 시작 대기로 넘기지 마세요.**

`compare_scenarios()`의 각 결과에는 `seed`, `arrivals`, `baseline`, `policy`, `reduction`이 들어갑니다. `baseline`과 `policy`에는 한 회차의 전체 결과를 넣고, `reduction`은 기준의 마지막 대기에서 비교의 마지막 대기를 뺀 값입니다.

`summarize()`는 `count`, `mean`, `stddev`, `minimum`, `maximum`을 반환합니다. 빈 자료는 개수 0 / 나머지 값 `None`, 자료 하나의 표본 표준편차는 `None`입니다. **자료 없음과 실제 값 0을 구분하고, 계산 중에는 반올림하지 마세요.**

이번 실험은 기존 도시와 별도로 진행합니다. 도로와 서비스 대상은 고정하고 전력 / 급수는 충분하다고 가정합니다. 확충 비용, 추가 수요, 대기 포기, 환자 우선순위는 계산하지 않습니다. 결과는 이 조건에서의 교육용 예제이며, 실제 병원 통계나 개인별 평균 대기시간을 뜻하지 않습니다.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/validation_rules.py`에서 해당 함수의 설명과 TODO 주석을 읽습니다.
2. `pass` 자리에 코드를 작성합니다. 주석만 있는 TODO는 그 아래에 코드를 추가합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 아래 코드는 실행되지 않습니다. 제공된 입력 검사는 유지하세요.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. TODO 2, 4, 6은 여러 부분으로 나뉘어 있으므로 각 부분을 함께 완성합니다.

| 단계 | 구현할 함수            | 이번 단계에서 할 일                                | 검사 명령                                        |
| ---- | ---------------------- | -------------------------------------------------- | ------------------------------------------------ |
| 1    | `is_valid_step`        | 결과의 인원과 대기열 규칙을 검사                   | `python skeleton/checks_validation.py --stage 1` |
| 2    | `make_arrivals`        | 지역 난수 생성기로 시간별 방문 목록 생성           | `python skeleton/checks_validation.py --stage 2` |
| 3    | `run_scenario`         | 대기 0명부터 실행하고 시간별 기록 / 최종 대기 반환 | `python skeleton/checks_validation.py --stage 3` |
| 4    | `summarize`            | 개수 / 평균 / 표본 표준편차 / 범위 계산            | `python skeleton/checks_validation.py --stage 4` |
| 5    | `compare_scenarios`    | 같은 입력으로 두 용량을 실행해 감소 인원 비교      | `python skeleton/checks_validation.py --stage 5` |
| 6    | `sensitivity_analysis` | 여러 용량의 최종 대기 목록과 요약 통계 계산        | `python skeleton/checks_validation.py --stage 6` |

`--stage 3`은 **1~3단계를 모두 검사**합니다. 뒤 단계에서 앞 단계 함수를 사용하므로 앞 단계의 실패부터 해결하세요. 단계를 생략한 `python skeleton/checks_validation.py`는 전체 6단계를 검사합니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[미구현] 1단계: is_valid_step
validation_rules.py를 작성하고 같은 명령을 다시 실행하세요.
```

| 표시       | 의미와 다음 행동                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------ |
| `[통과]`   | 해당 검사에서 기대한 결과가 나왔습니다.                                                          |
| `[미구현]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요.                     |
| `[실패]`   | 기대값과 실제 값이 다르거나 실행 중 예외가 발생했습니다. 출력된 입력 / 결과 / 오류를 확인하세요. |

검사기는 처음 실패한 사례에서 멈춥니다. 문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 전체가 통과하면 `선택한 검사를 모두 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, 미구현 `2`입니다.

## 6. 결과를 비교해 보기

### 실험 A: 한 회차 다시 실행하기

1. 기본 설정에서 시작 시드를 101로 둡니다.
2. 「방문 인원 생성」을 두 번 눌러 두 입력이 같은지 확인합니다.
3. 「1회 실행」을 두 번 누르고, 매번 다음 표와 같은 결과인지 확인합니다.

| 시간    | 방문 인원 | 기준 대기: 용량 8 | 비교 대기: 용량 10 |
| ------- | --------: | ----------------: | -----------------: |
| 1시간째 |         9 |                 1 |                  0 |
| 2시간째 |        14 |                 7 |                  4 |
| 3시간째 |        11 |                10 |                  5 |
| 4시간째 |        13 |                15 |                  8 |
| 5시간째 |         6 |                13 |                  4 |
| 6시간째 |        14 |                19 |                  8 |

인원 단위는 명, 용량 단위는 명/시간입니다. 기준의 첫 시간은 `min(0 + 9, 8) = 8`명을 진료하고 `0 + 9 - 8 = 1`명이 남습니다. 두 번째 시간은 이 1명에 새 방문 14명을 더해 계산합니다. 마지막 대기의 차이는 `19 - 8 = 11`명입니다.

### 실험 B: 30회 반복 비교하기

시드 101부터 30회, 실행 시간 6시간, 방문 6~14명, 기준 / 비교 용량 8 / 10명으로 「반복 비교」를 실행하세요.

| 지표                      |      결과 |
| ------------------------- | --------: |
| 기준의 6시간 후 평균 대기 |   12.60명 |
| 비교의 6시간 후 평균 대기 | 약 3.93명 |
| 평균 감소 인원            | 약 8.67명 |

## 8. 완료 확인과 모범 답안

함수 6개를 완성하면 통합 검사와 최종 검사를 실행하세요.

```sh
python skeleton/checks_validation.py --integration
python skeleton/checks_validation.py --release
```

`--integration`은 기존 도시 연계와 실험 저장 / 복원 / 재현을 확인합니다. `--release`는 1~6단계, 통합, 이전 주차 회귀 검사를 모두 실행합니다.

실습 완료 전에 확인하세요.

- [ ] `python skeleton/checks_validation.py --release`의 모든 검사가 통과한다.
- [ ] 시드 101의 시간별 대기와 30회 평균이 위 표와 일치한다.
- [ ] 실험 전후에 기존 도시의 상태와 시간이 유지된다.
- [ ] 실험 JSON과 CSV를 저장하고, JSON을 다시 불러와 선택 회차를 재현할 수 있다.
- [ ] 동료가 설명 없이 실행 / 비교 / 저장을 해 보고, 막힌 지점의 조작 순서와 기대 / 실제 결과를 기록했다.
- [ ] 같은 입력 비교, 회차별 초기화, `None`과 0, 표본 표준편차, 실험 가정의 한계를 설명할 수 있다.

모범 답안의 검사와 화면은 다음 명령으로 확인할 수 있습니다.

```sh
python solution/checks_validation.py --release
python solution/app.py
```

구현을 비교할 때는 코드 모양뿐 아니라 **같은 입력에서 같은 결과가 나오는지, 입력과 기존 도시를 보존하는지** 함께 살펴보세요. 자동 검사 통과와 실제 도시를 설명하기에 가정이 적절한지는 별도로 판단해야 합니다.

발표할 PC에서 예제 실행 → 조건 변경 → 결과 비교 → 저장 순서로 리허설하고, 확인한 코드와 실험 기록을 함께 보관하세요. 이후 코드를 수정하면 관련 검사와 시연을 다시 합니다. 이전 수업 내용은 [인터페이스 실습 안내](skeleton/README_interface.md)에서 확인할 수 있습니다.
