# 토지 이용과 건물 성장 실습

5×4 격자에 용도지역과 건물을 배치하고, 도로 / 주변 환경 / 입주 수요에 따라 주택 인구가 어떻게 바뀌는지 구현하는 Python 실습입니다.

**[skeleton/model.py](skeleton/model.py)의 TODO 1~7을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 리스트와 딕셔너리로 용도지역과 건물 정보를 구분하기
- 조건문과 반복문으로 점유율, 도로 접근성, 주변 환경 점수를 계산하기
- 주택별 입주 요청과 도시 전체의 실제 입주 배정을 구분하기
- 하루 시작 상태를 보존하면서 모든 주택의 다음 날 상태 만들기
- 예상 결과와 실제 결과를 비교하며 구현 확인하기

| 폴더                  | 용도                                                              |
| --------------------- | ----------------------------------------------------------------- |
| [skeleton](skeleton/) | 학생용 코드입니다. `model.py`에 구현할 부분이 남아 있습니다.      |

## 3. 도시 데이터를 읽는 방법

### 좌표와 건물

- 지도는 가로 5칸, 세로 4칸입니다. `x`는 0~4, `y`는 0~3입니다.
- 좌표는 `(x, y)`로 표현하지만, 셀을 읽을 때는 **`city["grid"][y][x]`** 순서입니다.
- 각 셀에는 지형 `terrain`, 도로 유무 `road`, 용도지역 `zone`, 건물 ID `building_id`가 있습니다.
- `city["buildings"]`는 건물 ID를 키로, 건물 정보 딕셔너리를 값으로 저장합니다.

예를 들어 기본 도시의 `(2, 1)` 셀을 읽으면 `building_id`가 `"P"`입니다. 실제 공원 정보는 `city["buildings"]["P"]`에서 찾습니다. **셀에 저장하는 것은 건물 정보 전체가 아니라 ID입니다.** ID가 `None`이면 건물이 없으므로 건물 정보를 조회하지 않습니다.

| 값                     | 의미                                                                        |
| ---------------------- | --------------------------------------------------------------------------- |
| `city["day"]`          | 지난 날짜. 처음은 0일이며, 1 tick은 1일입니다.                              |
| `city["budget"]`       | 도시 예산, 단위는 코인                                                      |
| `city["demand"]`       | 도시 전체에서 입주를 기다리는 인구                                          |
| `city["departed"]`     | 도시를 떠난 누적 인구                                                       |
| `building["status"]`   | `"construction"`은 건설 중, `"operating"`은 운영 중, `"closed"`는 운영 중지 |
| `house["population"]`  | 해당 주택에 현재 거주하는 인구                                              |
| `building["workers"]`  | 상점 / 공장의 점유 일자리 수. 전체 주택 인구에 더하지 않습니다.             |
| `building["capacity"]` | 건물의 수용량. 공원에는 이 항목이 없습니다.                                 |

### 용도지역과 건물 배치

| 건물 종류 | `kind` 값   | 필요한 용도지역 |
| --------- | ----------- | --------------- |
| 주택      | `"house"`   | `"R"`           |
| 상점      | `"shop"`    | `"C"`           |
| 공장      | `"factory"` | `"I"`           |
| 공원      | `"park"`    | 미지정(`None`)  |

**용도지역 지정과 건물 배치는 별도 작업입니다.** 주거 지역을 지정하는 것만으로 주택이 생기지는 않습니다. 건물은 도로와 다른 건물이 없는 땅에 배치하며, 물 위에는 도로 / 용도지역 / 건물을 둘 수 없습니다.

건설 가능 여부와 성장 조건도 구분합니다. 주변에 도로가 없어도 건물은 배치할 수 있지만, 주택 인구의 성장에는 도로가 필요합니다.

### 성장 / 쇠퇴와 수요 배정

도로 접근성과 환경 점수는 **상하좌우만** 검사합니다. 대각선은 포함하지 않습니다. 환경 점수 `E`는 운영 중인 이웃 공원마다 `+2`, 공장마다 `-3`을 합한 값입니다.

운영 중인 주택에 다음 규칙을 적용합니다.

| 조건                    | 입주 요청 | 전출     |
| ----------------------- | --------- | -------- |
| 도로가 없거나 `E <= -1` | 0명       | 최대 1명 |
| 도로가 있고 `E == 0`    | 0명       | 0명      |
| 도로가 있고 `E >= 1`    | 최대 2명  | 0명      |

입주 요청은 빈자리를 초과할 수 없고, 전출은 현재 인구를 초과할 수 없습니다. 운영 중인 주택이 아니면 둘 다 0입니다. 상점과 공장의 점유 일자리 수는 고정됩니다.

**입주 요청과 실제 입주는 다릅니다.** A와 B가 각각 2명을 요청해도 대기 인구가 3명이면, 건물 ID 오름차순으로 A에 2명, B에 1명을 배정합니다. 대기 인구가 0이어도 주택은 입주를 요청할 수 있지만, 실제 입주 인원은 0명입니다. 전출자는 대기 인구로 돌아오지 않습니다.

지난 실습과 달리 이번 실습의 외부 전력은 `True`로 고정합니다. 공원 반경 설정 대신 상하좌우 시설의 환경 점수를 사용하며, 이전 실습의 JSON 파일은 형식이 달라 불러올 수 없습니다.

### 예산 규칙

| 규칙                  | 기본값 | 의미                                               |
| --------------------- | -----: | -------------------------------------------------- |
| `growth_per_day`      |      2 | 조건을 만족하는 주택 한 채의 하루 최대 입주 요청량 |
| `tax_per_person_day`  |      3 | 하루 시작 인구 1명당 세금 3코인                    |
| `maintenance_per_day` |     10 | 도시 전체에서 하루에 한 번 차감하는 유지비 10코인  |

하루 뒤 예산은 `시작 예산 + 시작 총인구 × 1인당 세금 - 하루 유지비`입니다. **오늘 새로 입주한 사람은 오늘 세금 계산에 포함하지 않습니다.** 세금과 날짜 갱신 코드는 이미 제공되어 있으며, 입주 요청의 하루 한도는 `city["rules"]["growth_per_day"]`에서 읽으세요.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/model.py`에서 해당 함수와 TODO 주석을 읽습니다.
2. TODO 주석의 안내에 따라 코드를 작성합니다. TODO 7은 A~D의 임시 값 `(0, 0)`, `{}`, `0`을 계산 결과로 바꿉니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 함수 실행이 그 자리에서 멈춥니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. TODO 7은 A~D를 함께 완성합니다.

| 단계 | 구현할 함수         | 이번 단계에서 할 일                           | 검사 명령                             |
| ---- | ------------------- | --------------------------------------------- | ------------------------------------- |
| 1    | `can_build`         | 건물 종류와 용도지역이 맞는지 판단            | `python skeleton/checks.py --stage 1` |
| 2    | `occupancy`         | 점유율을 반환하고 공원 / 수용량 0 처리        | `python skeleton/checks.py --stage 2` |
| 3    | `road_access`       | 상하좌우에 도로가 있는지 확인                 | `python skeleton/checks.py --stage 3` |
| 4    | `environment_score` | 운영 중인 이웃 시설의 환경 점수 합산          | `python skeleton/checks.py --stage 4` |
| 5    | `growth_request`    | 입주 요청량과 전출량을 튜플로 반환            | `python skeleton/checks.py --stage 5` |
| 6    | `allocate_arrivals` | 대기 인구를 ID 순서대로 배정한 dict 반환      | `python skeleton/checks.py --stage 6` |
| 7    | `step`              | 인구 / 대기 / 누적 전출을 갱신한 새 도시 반환 | `python skeleton/checks.py --stage 7` |

`--stage 3`은 **1~3단계를 모두 검사**합니다. 뒤 단계에서 앞 단계 함수를 사용하므로 앞 단계의 실패부터 해결하세요. 단계를 생략한 `python skeleton/checks.py`는 전체 7단계를 검사합니다.

`neighbors4`, `total_population`, `place_building`은 제공된 함수를 그대로 사용합니다. 함수 이름과 매개변수도 유지해야 화면과 검사 코드가 여러분의 함수를 호출할 수 있습니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[미완성] TODO 1: 용도지역과 건물: TODO 1: 용도지역과 건물 종류의 대응을 확인하세요.
```

| 표시       | 의미와 다음 행동                                                             |
| ---------- | ---------------------------------------------------------------------------- |
| `[통과]`   | 해당 검사에서 기대한 결과가 나왔습니다.                                      |
| `[미완성]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]`   | 기대한 조건을 만족하지 못했습니다. 함께 출력된 안내와 구현을 비교하세요.     |
| `[오류]`   | 실행 중 예외가 발생했습니다. 오류 메시지와 파일 / 줄 번호를 확인하세요.      |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 전체가 통과하면 `요청한 모든 점검을 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, 미완성 `2`입니다. 검사는 GUI 없이 실행할 수 있습니다.

TODO 7에서는 **모든 요청을 `old`에서 모으고 → 수요를 배정한 뒤 → 결과를 `new`에 기록**합니다. `old`는 하루 시작 상태이고 `new`는 `deepcopy`로 만든 복사본입니다. 입력인 `old`를 바꾸면 건물의 계산 순서에 따라 결과가 달라질 수 있습니다.

**지도 편집과 입주 대기 인구 변경은 0일에만 가능합니다.** 하루를 진행하면 편집 도구가 잠깁니다. 다시 편집하려면 0일의 시작 상태로 돌아가거나 시나리오를 새로 선택하세요. 1일 이후의 JSON을 불러온 경우에는 `실험 시작으로`를 눌러도 그 파일의 시작 날짜로 돌아갑니다.

주택을 새로 배치하려면 `빈 지도`를 선택하고, 빈 땅에 `주거 R`을 지정한 뒤 같은 셀에 `주택`을 놓으세요. 건물이 있는 셀의 용도를 바꾸려면 먼저 건물을 삭제합니다. 공원은 용도가 지정되지 않은 셀에 놓습니다.

| 날짜 | A 인구 | B 인구 | 전체 인구 | 입주 대기 | 누적 전출 | 예산 |
| ---- | -----: | -----: | --------: | --------: | --------: | ---: |
| 0일  |      6 |      8 |        14 |         3 |         0 |  100 |
| 1일  |      8 |      9 |        17 |         0 |         0 |  132 |
| 2일  |      8 |      9 |        17 |         0 |         0 |  173 |

1일 예산은 `100 + 14 × 3 - 10 = 132`, 2일 예산은 `132 + 17 × 3 - 10 = 173`입니다.

A와 B의 환경이 모두 좋은데 B에 한 명만 입주한 이유를 설명해 보세요. 2일째에는 두 주택에 빈자리가 남아 있는데도 인구가 늘지 않는 이유도 설명해 보세요.

### 실험 B: 산업시설 인접 도시

`산업시설 인접 도시`를 선택하고, 지도를 수정하지 않은 상태에서 3일을 진행하세요.

| 날짜 | A 인구 | B 인구 | 전체 인구 | 입주 대기 | 누적 전출 | 예산 |
| ---- | -----: | -----: | --------: | --------: | --------: | ---: |
| 0일  |      6 |      8 |        14 |         5 |         0 |  100 |
| 1일  |      8 |      7 |        15 |         3 |         1 |  132 |
| 2일  |     10 |      6 |        16 |         1 |         2 |  167 |
| 3일  |     10 |      5 |        15 |         1 |         3 |  205 |

B 옆에 공원이 있는데도 인구가 줄어드는 이유와, 3일째에 대기 인구가 남아 있는데 A에 더 입주하지 못하는 이유를 설명해 보세요. `전체 주택 인구 + 입주 대기 + 누적 전출`의 합이 계속 19명인지도 확인하세요.

기본 도시의 초기 대기는 3명, 산업시설 인접 도시는 5명입니다. 환경 효과만 비교하려면 두 실험의 대기 인구를 같게 맞추세요. 산업시설 인접 도시에서 **0일에** 공장만 삭제한 경우와 비교하는 방법도 있습니다.

추가로 기본 도시에서 **0일에** A 주택 바로 아래 `(1, 2)`의 도로를 삭제한 뒤, 어느 주택에서 전출이 발생할지 예상하고 확인해 보세요. 보관할 도시 상태는 새 시나리오를 선택하기 전에 저장하세요.
