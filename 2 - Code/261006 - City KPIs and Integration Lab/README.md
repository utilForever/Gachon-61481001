# 도시 지표와 통합 실습

5×4 격자 도시에서 인구, 통근 접근성, 개발 가능 토지, 혼잡 시간을 계산하고, 시간에 따른 변화를 기록하는 Python 실습입니다. 완성한 지표 계산 코드를 도시 편집기와 교통 화면에 연결하고, 결과를 JSON과 CSV로 저장합니다.

**[skeleton/metrics.py](skeleton/metrics.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 지표마다 무엇을 세고 어떤 분모를 사용하는지 구분하기
- `0`, 도달 불가, 관측값 없음의 차이를 코드로 표현하기
- 같은 시각의 중복 기록을 막고 과거 상태를 독립적으로 보관하기
- 기본 / 혼잡 / 단절 도시를 비교하고 지표의 의미와 한계 설명하기
- 저장한 도시 상태를 복원해 실험을 이어 가기

## 3. 도시와 지표 데이터를 읽는 방법

### 좌표와 건물

| 데이터               | 읽는 방법                                                                |
| -------------------- | ------------------------------------------------------------------------ |
| `city["grid"][y][x]` | 좌표 `(x, y)`의 셀. `x`는 0~4, `y`는 0~3입니다.                          |
| `city["buildings"]`  | 건물 ID를 키로 쓰는 딕셔너리. 주택 / 상점 / 공장 / 공원을 포함합니다.    |
| `trips`              | 주민 한 명당 통근 한 건을 담은 리스트. `time_min`은 예상 이동시간입니다. |
| `observations`       | 관측 구간의 시작 시각, 길이, 대기 차량 수 등을 담은 리스트입니다.        |
| `history`            | 각 시각의 `minute`과 지표 값을 담은 기록 리스트입니다.                   |

셀의 `building_id`는 건물 정보 전체가 아닌 ID입니다. 예를 들어 `(0, 1)` 셀의 ID는 `"H"`이고, 주택 정보는 `city["buildings"]["H"]`에서 찾습니다. 인구는 운영 상태와 관계없이 모든 주택에서 합산하며, 건물 수는 공원을 제외하고 셉니다.

### 통근 지표와 빈 값

기본 KPI 도시에는 주택 H의 주민 6명과 주택 A의 주민 4명이 있습니다. 모든 주민이 상점 J로 한 번씩 통근한다고 가정합니다. 제공 코드가 주택과 목적지에 인접한 도로 사이의 최소 이동시간을 계산하며, 도달할 수 없는 주민도 통근 목록에 남깁니다.

- **접근성 비율** = 기준 시간 이내에 도달 가능한 주민 수 / 전체 예정 통근 인원
- **평균 통근 시간** = 도달 가능한 주민의 이동시간 합 / 도달 가능한 주민 수
- **중앙값 / P90** = 도달 가능한 주민의 이동시간 분포를 요약한 값. 제공 코드가 계산합니다.

평균은 건물별 평균이 아니라 **주민별 평균**입니다. 6명이 3분, 4명이 1분 걸리면 평균은 `(6 × 3 + 4 × 1) / 10 = 2.2분`입니다.

`time_min=0`은 유효한 이동시간이고 `time_min=None`은 도달 불가입니다. 화면의 `—`는 평균을 낼 사람이 없거나 아직 관측값이 없는 경우에 표시됩니다. **미구현 / 오류 / —**를 구분하고, 오류 내용은 화면 하단의 상태 메시지에서 확인하세요.

이동시간은 현재 대기열을 이용한 **예상 통근 시간**입니다. 시민이 실제로 이동을 끝낸 시간을 측정하는 모델은 아닙니다. KPI 화면의 `1분 진행`은 선택한 도로의 대기열을 갱신하며, 도시 편집기의 `1일 진행`과는 별개입니다.

### 개발 가능 토지와 혼잡 시간

개발 가능 셀은 **땅 / 도로 없음 / 건물 없음 / 보전 대상 아님 / 상하좌우 도로 인접**의 다섯 조건을 모두 만족해야 합니다. 용도지역은 추가 조건이 아닙니다. 기본 보전 셀은 `(1, 0)`이며, 이웃 좌표는 제공 함수 `neighbors4`로 확인합니다. 위쪽 행부터 같은 행에서는 왼쪽부터 확인하고, 도로가 여러 개 인접해도 같은 셀은 한 번만 셉니다.

| 값                            | 의미                                          |
| ----------------------------- | --------------------------------------------- |
| `observation["start_minute"]` | 관측 구간이 시작한 시각, 단위는 분            |
| `observation["duration_min"]` | 구간의 길이, 단위는 분                        |
| `observation["queue"]`        | 구간 시작 시점의 대기 차량 수, 단위는 대      |
| `threshold`                   | 이 값 이상이면 혼잡으로 판단하는 대기 차량 수 |

혼잡 시간은 조건을 만족하는 구간의 **길이**를 더합니다. 구간 길이가 `[2, 3, 1]`분이고 대기열이 `[4, 5, 9]`대, 기준이 5대라면 관측 시간은 6분, 혼잡 시간은 4분, 최대 대기열은 9대입니다. 관측값이 없으면 관측 / 혼잡 시간은 0분이고 최대 대기열은 `None`입니다.

### 기록과 스냅샷

`history`에는 같은 `minute`을 한 번만 기록합니다. `append_history`는 새 행을 추가하면 `True`, 같은 시각이 이미 있으면 기존 기록을 유지하고 `False`를 반환합니다. 입력 `kpis`는 수정하지 않습니다.

스냅샷은 `format`, `city`, `transport`, `history`, `settings`, `observations`를 담은 딕셔너리이며, `format`은 `"virtual-city-kpi-v1"`입니다. 기록과 스냅샷 모두 중첩된 리스트 / 딕셔너리까지 독립적이어야 합니다. **원본을 바꿔도 과거 기록은 그대로이고, 복사본을 바꿔도 원본은 그대로여야 합니다.** `deepcopy`와 파일 입출력 연결 코드는 제공됩니다.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/metrics.py`에서 해당 함수와 TODO 주석을 읽습니다.
2. `pass` 자리에 코드를 작성합니다. 주석만 있는 TODO는 그 아래에 코드를 추가합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 아래 코드는 실행되지 않습니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. TODO 3과 5는 A~B를 함께 완성합니다.

| 단계 | 구현할 함수              | 이번 단계에서 할 일                                  | 검사 명령                             |
| ---- | ------------------------ | ---------------------------------------------------- | ------------------------------------- |
| 1    | `summarize_city`         | 주택 인구와 공원을 제외한 건물 수를 합산             | `python skeleton/checks.py --stage 1` |
| 2    | `summarize_trips`        | 도달 가능한 인원, 기준 이내 인원, 이동시간 합을 계산 | `python skeleton/checks.py --stage 2` |
| 3    | `find_developable_cells` | 다섯 조건을 만족하는 좌표를 중복 없이 반환           | `python skeleton/checks.py --stage 3` |
| 4    | `summarize_congestion`   | 관측 / 혼잡 구간의 길이와 최대 대기열을 계산         | `python skeleton/checks.py --stage 4` |
| 5    | `append_history`         | 중복 시각을 거절하고 독립적인 기록 행을 추가         | `python skeleton/checks.py --stage 5` |
| 6    | `make_snapshot`          | 저장 형식과 다섯 항목을 담아 독립적인 상태를 반환    | `python skeleton/checks.py --stage 6` |

`--stage 3`은 **1~3단계를 모두 검사**합니다. 단계를 생략한 `python skeleton/checks.py`는 전체 6단계를 검사합니다. 한 함수만 확인하려면 기존 명령인 `python skeleton/checks.py --task 3`으로 3번만 검사할 수 있습니다.

함수 이름과 매개변수, 반환 키는 유지하세요. 초기값, 순회 구조, 반환 형식은 코드 틀에 제공되어 있습니다. TODO 2의 비율 / 평균 계산과 빈 분모 처리, TODO 6의 마지막 깊은 복사도 제공되므로, 각 TODO가 요구하는 빈 부분을 작성해 연결합니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[미완성] TODO 1: 인구와 건물 수: TODO 1: 인구와 건물 수를 계산하세요.
```

| 표시       | 의미와 다음 행동                                                             |
| ---------- | ---------------------------------------------------------------------------- |
| `[통과]`   | 해당 검사에서 기대한 결과가 나왔습니다.                                      |
| `[미완성]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]`   | 기대값과 실제 값이 다릅니다. 함께 출력된 두 값을 비교하세요.                 |
| `[오류]`   | 실행 중 예외가 발생했습니다. 오류 메시지와 파일 / 줄 번호를 확인하세요.      |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 요청한 검사가 모두 통과하면 `요청한 모든 점검을 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, 미완성 `2`입니다. 실패와 미완성이 함께 있으면 `1`을 반환합니다. 검사는 GUI 없이 실행할 수 있습니다.

개별 검사의 도시는 KPI 화면의 도시와 다를 수 있습니다. 예를 들어 TODO 1 검사는 주택 H만 있는 도시를 사용하고, KPI 화면은 주택 A를 추가한 도시를 사용합니다. 특정 기대값을 함수에 직접 넣지 말고 입력 데이터에서 계산하세요.

6단계를 마치면 다음 명령으로 지표 계산, 시간 진행, JSON 저장 / 복원, CSV 출력까지 함께 확인합니다. 통합 검사는 누적 검사와 별도로 실행합니다.

```sh
python skeleton/checks.py --integration
```

| 도로망과 교통                       | 경로와 교통 상태를 확인하고 **현재 상태 적용**을 눌러 반영합니다.         |
| 상태 저장 / 불러오기 / CSV 내보내기 | 실험 상태를 JSON으로 저장 / 복원하거나 기록을 CSV로 내보냅니다.           |

설정을 적용하거나 도시 / 관찰 도로를 변경하면 기존 기록과 관측값을 지우고 0분부터 다시 시작합니다. 비교할 결과는 먼저 JSON이나 CSV로 저장하세요. 설정 변경 후 새 실험을 시작해도 대기 차량 수가 자동으로 0이 되지는 않습니다. 대기 0대에서 시작하려면 설정의 대기 차량 값도 함께 바꾸세요.

교통 창의 **일자리 접근성**은 선택한 출발 도로에서 도달할 수 있는 일자리 수입니다. KPI 화면의 **통근 접근성**은 전체 주민 중 상점 J에 기준 시간 이내로 도달하는 주민의 비율입니다. 두 값의 대상과 단위를 구분하세요.

### 저장하고 다시 불러오기

1. 기본 도시에서 5분 진행한 뒤 **상태 저장**으로 JSON 파일을 저장합니다.
2. 1분을 더 진행한 뒤 **불러오기**로 저장한 파일을 엽니다.
3. 5분 상태와 기록 6행이 복원됐는지 확인하고, 다시 1분을 진행합니다.
4. **CSV 내보내기**로 지표 기록을 저장해 표나 스프레드시트에서 확인합니다.

JSON에는 도시, 교통, 설정, 관측값, 지표 기록이 함께 저장됩니다. CSV에는 시각별 지표와 통근 / 혼잡 기준, 관찰 도로, 보전 셀 등의 실험 조건이 들어갑니다. CSV는 결과 분석용이며, 도시 상태 복원에는 JSON을 사용합니다.

| 예제 파일                                                                                                                                                                                                    | 용도와 여는 위치                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| [kpi_default_5min.json](skeleton/examples/kpi_default_5min.json)                                                                                                                                             | 기본 도시의 5분 저장 상태. **KPI 화면 → 불러오기**에서 엽니다.                               |
| [traffic_default.json](skeleton/examples/traffic_default.json), [traffic_congested.json](skeleton/examples/traffic_congested.json), [traffic_disconnected.json](skeleton/examples/traffic_disconnected.json) | 교통 시나리오. **도로망과 교통 → 불러오기**에서 열고 필요하면 **현재 상태 적용**을 누릅니다. |
| [distribution_comparison.json](skeleton/examples/distribution_comparison.json)                                                                                                                               | 평균이 같은 두 집단의 설명 자료. 편집기에서 읽습니다.                                        |
| [expected_results.json](skeleton/expected_results.json)                                                                                                                                                      | 기대 결과 비교 자료. 편집기에서 읽습니다.                                                    |

예제는 두 폴더에 동일하게 들어 있습니다. 교통 JSON과 KPI 저장 JSON은 형식이 다르므로 표에 적힌 화면에서 여세요. 교통 예제에는 KPI 도시에서 추가한 주택 A가 없으므로, 해당 파일을 적용한 뒤의 인구와 지표는 실험 A의 표와 다를 수 있습니다.

## 6. 결과를 비교해 보기

### 실험 A: 세 도시의 초기 상태 비교

각 시나리오 버튼을 누른 직후인 **0분**, 통근 기준 **4분**의 결과입니다. 세 도시의 인구는 10명이고 공원을 제외한 건물 수는 4동입니다.

| 시나리오 | 평균 통근 시간 | 기준 이내 비율 | 도달 불가 | 개발 가능 셀 | 현재 대기열 |
| -------- | -------------- | -------------- | --------- | ------------ | ----------- |
| 기본     | 2.2분          | 100%           | 0명       | 2개          | 0대         |
| 혼잡     | 3.4분          | 40%            | 0명       | 2개          | 20대        |
| 단절     | `—` (`None`)   | 0%             | 10명      | 4개          | 0대         |

0분에는 아직 관측한 구간이 없으므로 혼잡 시간은 0분, 관측 최대 대기열은 `None`입니다. 단절 도시의 개발 가능 셀이 늘었다고 교통 접근성까지 좋아진 것은 아닙니다. 각 지표가 실제로 검사하는 조건을 생각해 보세요.

### 실험 B: 기본 도시에서 5분 진행

기본 도시를 새로 선택한 뒤 설정을 바꾸지 않고 **5분 진행**을 누릅니다. 관찰 도로는 `(1, 2)`, 유입은 8대/분, 처리 용량은 5대/분, 혼잡 기준은 5대입니다.

| 확인 항목                       | 5분 결과                |
| ------------------------------- | ----------------------- |
| 현재 대기열                     | 15대                    |
| 관측 시간 / 혼잡 시간           | 5분 / 3분               |
| 관측 최대 대기열                | 12대                    |
| 평균 통근 시간 / 기준 이내 비율 | 3.4분 / 40%             |
| 기록 행 수                      | 6행: 0, 1, 2, 3, 4, 5분 |

관측은 각 `[t, t+1)` 구간의 **시작 시점** 대기열을 사용합니다. 0~5분 사이에 관측한 값은 `0, 3, 6, 9, 12`대이므로 최대값은 12대입니다. 5분 현재 대기열 15대는 다음 구간의 관측값이 됩니다.

**지표 계산**을 여러 번 눌러도 기록은 6행이어야 합니다. 세 시나리오의 0~5분 전체 기대 결과는 [skeleton/expected_results.json](skeleton/expected_results.json)에서 확인할 수 있습니다.

### 실험 C: 평균이 같은 두 집단

분포 비교 예제에서 X는 10명 모두 4분, Y는 8명이 1분이고 2명이 16분 걸립니다. 기준 시간은 4분입니다.

| 집단 | 평균 | 중앙값 | P90  | 기준 이내 비율 |
| ---- | ---- | ------ | ---- | -------------- |
| X    | 4분  | 4분    | 4분  | 100%           |
| Y    | 4분  | 1분    | 16분 | 80%            |

평균이 같아도 일부 주민이 겪는 이동시간은 크게 다를 수 있습니다. 이 자료는 도시 실행 결과가 아닌 설명용 예제입니다. 제공 코드의 P90은 이동시간을 정렬한 뒤 `ceil(0.9 × 인원 수)`번째 값을 사용합니다.

| 코드를 썼는데 계속 미완성                  | 파일 저장 여부와 해당 함수의 `raise NotImplementedError(...)` 줄을 확인합니다.                                                                  |

| 0분 통근이 도달 불가로 집계됨              | `if time` 대신 `time is not None`으로 도달 가능 여부를 구분했는지 확인합니다.                                                                   |

| 현재 대기열과 최대 대기열이 다름           | 최대값은 관측한 구간의 시작 시점 값을 사용합니다. 기본 도시 5분의 현재 15대 / 최대 12대는 정상입니다.                                           |
| 과거 기록이나 저장 상태까지 바뀜           | 원본을 그대로 추가하거나 얕게 복사하지 않았는지 확인합니다. 중첩 자료도 `deepcopy`로 복사해야 합니다.                                           |
| 기록이 쌓이지 않거나 CSV를 내보낼 수 없음  | 지표 표와 화면 하단 안내에서 TODO 1~4의 오류를 확인하고, TODO 5의 중복 검사와 새 행 추가를 점검합니다.                                          |
| JSON을 불러올 수 없거나 예제 수치가 다름   | KPI JSON과 교통 JSON을 해당 화면에서 열었는지, KPI 도시의 주택 A가 포함되어 있는지 확인합니다.                                                  |
