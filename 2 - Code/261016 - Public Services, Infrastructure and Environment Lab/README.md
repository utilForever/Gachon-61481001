# 공공서비스 / 기반시설 / 환경 실습

병원 서비스 권역과 대기열, 전력 배분, 급수, 폐기물, 오염물질 이동을 구현하는 Python 실습입니다. 도로와 기반시설의 상태가 서비스 공급에 어떤 영향을 주는지 관찰합니다.

**[skeleton/service_rules.py](skeleton/service_rules.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다. 이전 실습의 도시 / 교통 / 행위자 기능은 구현된 상태로 제공됩니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 딕셔너리에 저장한 이동 시간과 인구로 서비스 권역 계산하기
- 수요와 처리 용량으로 대기열의 변화 계산하기
- 제한된 전력을 우선순위에 따라 배분하기
- 물과 폐기물의 유입 / 유출 / 저장을 구분하고 양의 보존 확인하기
- 같은 시작 상태를 기준으로 오염물질 이동시키기
- 예상 결과와 실제 결과를 비교하며 구현 확인하기

## 2. 준비하고 실행하기

### 실행 환경 확인

Python 3와 Tkinter가 필요합니다. Python 3.11에서 확인했으며, 실행 코드에서는 표준 라이브러리만 사용하므로 별도의 `pip install`은 필요하지 않습니다.

압축 파일로 받았다면 폴더 전체를 해제하세요. **이 문서의 모든 터미널 명령은 `README.md`, `skeleton`, `solution`이 함께 있는 폴더에서 실행합니다.**

```sh
python --version
python -m tkinter
```

두 번째 명령으로 테스트 창이 열리면 닫으세요. Windows에서 Tkinter가 없다면 Python 설치 프로그램의 Tcl/Tk 항목을 확인하세요. 환경에 따라 `python` 대신 `python3` 또는 Windows의 `py`를 사용할 수 있습니다.

### 실습 화면 열기

학생용 프로그램은 다음 명령으로 실행합니다.

```sh
python skeleton/app.py
```

처음에는 서비스 권역에 `미구현`이 표시되고 화면 아래 상태 메시지에 남은 TODO가 나타납니다. 실행 중 발생한 오류도 이곳에서 확인할 수 있습니다. **TODO 6개를 모두 완성하기 전에는 서비스 시간을 진행할 수 없습니다.** 먼저 단계별 검사로 구현을 확인하세요.

프로그램이 실행 중이면 같은 터미널에서 다음 명령을 입력하기 전에 창을 닫으세요. 코드를 수정한 뒤에는 파일을 저장하고 프로그램을 다시 실행해야 변경 사항이 반영됩니다.

## 3. 서비스 데이터를 읽는 방법

### 지역과 서비스 상태

`session`은 도시 / 교통 / 행위자를 포함한 실험 전체 상태이며, `state = session["services"]`는 그중 공공서비스 상태입니다. 학생 함수에는 전체 상태가 아니라 계산에 필요한 값이 전달됩니다.

| 값                                            | 의미                                                                 |
| --------------------------------------------- | -------------------------------------------------------------------- |
| `travel_minutes["A"]`                         | A 지역에서 병원까지의 이동 시간. 단위는 분이며, 경로가 없으면 `None` |
| `populations["A"]`                            | A 지역의 서비스 수요 인구                                            |
| `demands_kw["hospital"]`                      | 병원의 전력 수요. 단위는 kW                                          |
| `priority`                                    | 전력을 배분할 시설 이름의 순서                                       |
| `state["hour"]`                               | 진행한 시간. 처음은 0시간이며, 서비스의 1 tick은 1시간               |
| `state["queue"]`                              | 진료받지 못하고 기다리는 인원                                        |
| `state["water_stored"]`                       | 물탱크에 남은 물. 단위는 m³                                          |
| `state["battery_kwh"]`                        | 비상전원에 남은 에너지. 단위는 kWh                                   |
| `state["waste_city"]`, `state["waste_plant"]` | 도시 / 처리시설에 남은 폐기물. 단위는 t                              |
| `state["pollution"]`                          | 서쪽에서 동쪽 순서의 셀별 오염량 목록                                |

예를 들어 `travel_minutes["A"]`가 `4`이고 `populations["A"]`가 `100`이면, A 지역의 100명이 병원까지 4분에 이동할 수 있다는 뜻입니다. **지역 이름은 딕셔너리의 키이며, 이동 시간과 인구는 서로 다른 값입니다.**

### 입력을 읽는 함수와 상태를 바꾸는 코드

`service_rules.py`의 여섯 함수는 입력을 읽어 새 결과를 반환합니다. 입력으로 받은 목록과 딕셔너리를 직접 변경하지 마세요. 반환한 값으로 실제 서비스 상태를 갱신하는 일은 `service_support.py`가 처리합니다.

전력 `kW`는 공급 능력이고 에너지 `kWh`는 저장한 양입니다. 예를 들어 30 kW를 한 시간 사용하면 배터리에서 30 kWh가 줄어듭니다. 병원까지의 이동 시간은 분, 서비스 진행은 시간 단위라는 점도 구분하세요.

### 서비스 권역

`travel_minutes`와 `populations`는 지역 ID를 키로 사용하는 딕셔너리입니다. 이동 시간이 `limit_minutes` **이하**인 지역을 권역에 포함합니다. `None`은 경로가 없다는 뜻이며, 이동 시간 `0`은 도달 가능한 값입니다.

| 반환 키                  | 의미                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| `covered`                | 권역에 포함된 지역 ID 목록. `populations`를 순회한 순서를 유지합니다. |
| `population`             | 권역에 포함된 인구의 합                                               |
| `ratio`                  | 권역 인구 / 전체 인구. 전체 인구가 0이면 `0`                          |
| `unreachable_population` | 이동 시간이 `None`인 지역의 인구 합                                   |

기준 시간을 초과한 지역과 경로가 없는 지역을 구분하세요. 예를 들어 이동 시간이 A 4분, B 8분, C 12분, D 20분이고 각 지역이 100명이라면, 15분 권역은 A·B·C, 인구는 300명, 비율은 `0.75`입니다.

### 병원 대기열

기존 대기 인원 `queue`에 새 요청 `arrivals`를 더합니다. 처리 용량 `capacity`를 넘지 않는 인원을 진료하고, 나머지를 다음 시간으로 넘깁니다.

- 반환값: `{"served": 실제 진료 인원, "queue": 다음 대기 인원}`
- 보존 관계: `기존 대기 + 새 요청 = 실제 진료 + 다음 대기`
- 예: 대기 0명, 요청 10명, 용량 8명이면 진료 8명, 다음 대기 2명입니다.

### 전력 배분

`priority`의 순서대로 시설에 전력을 배분합니다. 각 시설의 배분량은 해당 시설의 수요와 남은 공급량을 넘을 수 없습니다. 공급이 소진되어도 뒤의 시설을 결과에서 빠뜨리지 않고 배분량을 `0`으로 기록합니다.

- 반환값: 시설 이름을 키로, 배분 전력량을 값으로 갖는 딕셔너리
- 기본 우선순위: `hospital` → `pump` → `housing` → `industry`
- 기본 수요: 병원 30, 펌프 20, 주거 50, 산업 20 kW
- 공급이 100 kW이면 각각 30, 20, 50, 0 kW를 배분합니다.

### 물탱크

저장량 `stored_m3`과 유입량 `inflow_m3`을 합친 뒤 수요 `demand_m3`만큼 공급합니다. 물이 부족하면 가능한 만큼만 공급하고, 공급 후 남은 물 중 저장 용량 `capacity_m3`을 넘는 양은 넘침으로 처리합니다.

- 반환 키: `stored`는 다음 저장량, `supplied`는 공급량, `unmet`은 미충족 수요, `overflow`는 넘친 양입니다.
- 보존 관계: `기존 저장량 + 유입량 = 공급량 + 다음 저장량 + 넘침`
- 수요 관계: `수요 = 공급량 + 미충족 수요`

### 폐기물

도시의 기존 폐기물 `city_t`에 발생량 `generated_t`를 더하고, 수거 능력 `collection_t` 이내에서 처리시설로 옮깁니다. 시설의 기존 폐기물 `plant_t`와 이번에 수거한 양을 합쳐 처리 능력 `treatment_t` 이내에서 처리합니다.

- 반환 키: `city`는 도시에 남은 양, `plant`는 시설에 남은 양, `collected`는 수거량, `processed`는 처리량입니다.
- 이번에 수거한 폐기물도 같은 단계에서 처리할 수 있습니다.
- 보존 관계: `기존 도시량 + 기존 시설량 + 발생량 = 다음 도시량 + 다음 시설량 + 처리량`

### 오염물질 이동

`amounts`는 서쪽에서 동쪽 순서의 오염량 목록입니다. 각 셀은 **갱신 전 자신의 양**에 `move_ratio`를 곱한 만큼 바로 동쪽 셀로 보냅니다. 마지막 셀은 경계 밖으로 보내지 않습니다. 모든 이동을 반영한 뒤 각 셀에서 `removal_ratio` 비율만큼 제거합니다.

- 반환값은 새 오염량 목록이며, 원본 `amounts`는 유지합니다.
- 이번 단계에서 받은 양을 같은 단계에 다시 동쪽으로 보내면 안 됩니다.
- 예: `[100, 0, 0]`, 이동 비율 `0.2`, 제거 비율 `0.1`이면 `[72, 18, 0]`입니다.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/service_rules.py`에서 해당 함수의 설명과 TODO 주석을 읽습니다.
2. `pass` 자리에 코드를 작성합니다. 번호를 붙인 힌트와 확인 예를 활용하세요.
3. 구현한 함수의 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** `return` 아래에 남겨 두어도 화면의 미구현 검사에서 감지됩니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. 화면으로 확인하려면 프로그램을 닫고 다시 실행합니다.

| 단계 | 구현할 함수           | 이번 단계에서 할 일                                        | 검사 명령                                      |
| ---- | --------------------- | ---------------------------------------------------------- | ---------------------------------------------- |
| 1    | `service_coverage`    | 권역 지역 / 인구 / 비율과 경로가 없는 인구 반환            | `python skeleton/checks_services.py --stage 1` |
| 2    | `advance_queue`       | 실제 진료 인원과 다음 대기 인원 반환                       | `python skeleton/checks_services.py --stage 2` |
| 3    | `allocate_power`      | 우선순위대로 남은 전력을 나누어 시설별 배분량 반환         | `python skeleton/checks_services.py --stage 3` |
| 4    | `update_water`        | 저장 / 공급 / 미충족 수요 / 넘침 계산                      | `python skeleton/checks_services.py --stage 4` |
| 5    | `update_waste`        | 도시 / 시설의 잔량과 수거 / 처리량 계산                    | `python skeleton/checks_services.py --stage 5` |
| 6    | `transport_pollution` | 같은 시작 목록으로 동쪽 이동 후 제거를 적용한 새 목록 반환 | `python skeleton/checks_services.py --stage 6` |

`--stage 3`은 TODO 1~3을 **누적 검사**합니다. 옵션을 생략하면 전체 6개 TODO를 검사합니다. 모두 완성하면 통합 검사까지 실행하세요.

```sh
python skeleton/checks_services.py
python skeleton/checks_services.py --integration
```

통합 검사는 기본 조건의 시간 진행, 상태 저장 / 복원, 침수 조건의 경로 단절을 확인합니다. `--stage`와 `--integration`은 함께 지정하지 않습니다. 검사는 GUI 없이 실행할 수 있습니다.

처음 1단계를 검사하면 다음처럼 표시됩니다.

```text
[미구현] TODO 1: TODO 1: 서비스 권역에 포함된 지역과 인구를 계산하세요. / service_rules.py를 작성하세요.
1개 항목을 구현한 뒤 다시 확인하세요.
```

| 표시       | 의미와 다음 행동                                                                        |
| ---------- | --------------------------------------------------------------------------------------- |
| `[통과]`   | 해당 검사의 기대값과 일치합니다.                                                        |
| `[미구현]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다.                                    |
| `[실패]`   | 기대값과 다르거나 실행 중 다른 예외가 발생했습니다. 오류 종류와 검사 코드를 확인하세요. |

선택한 검사를 모두 통과하면 `선택한 검사를 모두 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 `1`, 미구현 `2`입니다. 실패와 미구현이 함께 있으면 `1`을 반환합니다. 문법·들여쓰기 오류는 검사 결과가 출력되기 전에 실행을 중단할 수 있습니다.

| 기반시설과 환경 | 전력 배분과 비상전원, 물탱크 저장량, 폐기물, 오염물질, 소음과 빗물 유출 예시    |
| 시간별 기록     | 매시간 권역 비율, 경로가 없는 인구, 진료 / 대기 인원, 물 / 배터리 / 폐기물 상태 |

서비스 수요는 A·B·C·D 각각 100명, 총 400명으로 설정되어 있습니다. 행위자 탭의 시민 3명과는 별도의 집계입니다. **교통의 분, 공공서비스의 시간, 행위자의 월, 이웃 실험의 회차는 따로 진행됩니다.**

같은 도시에서 조건을 선택한 뒤 `조건 적용 / 초기화`를 누르세요. 현재 도로는 유지하면서 서비스 상태와 시간별 기록을 0시간으로 초기화합니다. `1시간 진행`, `6시간 진행`, `24시간 진행`으로 변화를 관찰할 수 있습니다.

### 저장과 결과 정리

- `상태 저장`으로 도시 / 교통 / 행위자 / 서비스 상태와 기록을 JSON에 저장하고, `불러오기`로 복원합니다.
- `시간별 CSV`는 서비스 기록을 내보냅니다. 먼저 한 시간 이상 진행하세요. 분 단위 지표의 `CSV 내보내기`, 행위자의 `월별 CSV`와 구분합니다.
- 이웃 격자의 배치와 진행 상황은 상태 파일에 포함되지 않으며, 불러오면 초기화됩니다.
- 조건을 초기화하면 기존 서비스 기록이 지워지므로, 비교할 결과는 먼저 내보내세요.

결과를 정리할 때는 실험 조건, 관찰 시각, 대기 인원, 미충족 급수량, 배터리 사용량을 기록하고 원인을 설명하세요. 이 실습의 학교 배정 / 소음 / 빗물 유출은 제공된 예시이고, 오염량은 실제 대기 농도로 보정한 값이 아닙니다. 모델에 포함된 연결 관계와 단순화한 가정을 함께 살펴보세요.

## 6. 결과를 비교해 보기

### 실험 A: 기본 조건

1. `기본 도시`를 선택하고 `공공서비스 / 환경` 탭으로 이동합니다.
2. `기본 조건`을 선택하고 `조건 적용 / 초기화`를 누릅니다.
3. 도시와 도로를 바꾸지 않고 `1시간 진행`을 여섯 번 누릅니다.
4. `시간별 기록`에서 다음 표와 비교합니다.

| 시각  | 대기 인원(명) | 이번 급수량(m³) | 남은 저장수(m³) | 진료 용량(명) |
| ----- | ------------: | --------------: | --------------: | ------------: |
| 1시간 |             2 |               8 |               8 |             8 |
| 2시간 |             4 |               8 |               6 |             8 |
| 3시간 |             6 |               8 |               4 |             8 |
| 4시간 |             8 |               8 |               2 |             8 |
| 5시간 |            10 |               8 |               0 |             8 |
| 6시간 |            14 |               6 |               0 |             6 |

권역 안에서 매시간 10명이 요청합니다. 처음에는 용량 8명으로 진료하지만, 6시간째에는 급수가 부족해 진료 용량도 6명으로 줄어듭니다. 대기 인원이 늘어나는 폭이 달라지는 이유를 설명해 보세요.

### 실험 B: 조건 바꾸기

각 조건을 선택할 때마다 `조건 적용 / 초기화`를 누르고 0시간부터 다시 진행하세요. 비교할 기록은 초기화 전에 `시간별 CSV`로 내보냅니다.

| 조건      | 기본 조건과의 차이                                        | 관찰 질문                                            |
| --------- | --------------------------------------------------------- | ---------------------------------------------------- |
| 기본 조건 | 공급 100 kW, 급수 유입 6 m³/시간, 병원 기본 용량 8명/시간 | 물탱크가 비면 진료 용량과 대기열은 어떻게 바뀌나요?  |
| 정전      | 2·3시간째 외부 전력 공급 0 kW                             | 비상전원으로 병원 전력을 유지해도 급수는 충분한가요? |
| 침수      | 2·3시간째 도로 `(3, 1)` 통행 중단과 정전                  | 경로가 없는 인구와 서비스 공급은 어떻게 달라지나요?  |
| 병원 확충 | 병원 기본 용량을 10명/시간으로 증가                       | 병원만 확충하면 급수 부족도 해결되나요?              |
| 급수 확충 | 급수 유입을 8 m³/시간으로 증가                            | 물이 충분해도 대기열이 생기는 이유는 무엇인가요?     |

진료 용량은 병원 기본 용량에 전력 / 급수 충족 비율 중 작은 값을 곱하고 소수점을 내린 값입니다. 펌프 유입량은 펌프에 배분한 전력에 비례합니다. 비상전원은 병원에만 공급하며, 초기 배터리 에너지는 60 kWh입니다.

물탱크는 처음 10 m³, 최대 20 m³이며 수요는 시간당 8 m³입니다. 폐기물은 **24시간마다** 발생 8 t, 수거 능력 6 t, 처리 능력 5 t를 적용합니다. 오염물질은 처음 `[100, 0, 0]`에서 시작해 매시간 이동 20%, 제거 10%를 적용하며 추가 배출은 없습니다.

### 6시간 후 예상 결과

도시 / 도로 / 행위자 상태를 바꾸지 않은 기본 도시에서, 각 조건을 0시간부터 6시간까지 따로 진행한 결과입니다. 병원 권역은 처음 A 4분, B 8분, C 12분, D 20분으로 인구 75%를 포함합니다.

| 조건      | 6시간 후 대기(명) | 6시간째 급수량(m³) | 6시간째 진료 용량(명) | 남은 저장수(m³) | 남은 배터리(kWh) |
| --------- | ----------------: | -----------------: | --------------------: | --------------: | ---------------: |
| 기본 조건 |                14 |                  6 |                     6 |               0 |               60 |
| 정전      |                26 |                  6 |                     6 |               0 |                0 |
| 침수      |                26 |                  6 |                     6 |               0 |                0 |
| 병원 확충 |                 3 |                  6 |                     7 |               0 |               60 |
| 급수 확충 |                12 |                  8 |                     8 |              10 |               60 |

자세한 시간별 값은 [expected_results_services.json](skeleton/expected_results_services.json)에 있습니다. 이 파일은 비교용 자료이며, 앱의 `불러오기`에서 여는 상태 파일은 아닙니다. 최종 대기 인원이 같아도 과정이 같지는 않습니다. 정전과 침수의 2·3시간째 권역과 미배정 요청도 비교하세요.
