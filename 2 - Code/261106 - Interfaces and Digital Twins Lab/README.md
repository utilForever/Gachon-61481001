# 인터페이스, 시각화와 디지털 트윈 실습

가상 도시의 상태를 지도 / 선택 패널 / 그래프로 읽고, 공간 자료와 예제 관측값을 연결하는 Python 실습입니다.

**[skeleton/interface_rules.py](skeleton/interface_rules.py)의 TODO 1~6을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다. 예상 실습 시간은 약 90분입니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 딕셔너리에서 대상 / 시각 / 값 / 단위 / 출처를 읽어 표시하기
- 조건문으로 접근시간의 구간을 나누고 색상과 문구를 함께 반환하기
- 반복문으로 시계열을 만들고 같은 시각 / 대상의 이벤트 찾기
- 공간 좌표를 화면의 행 / 열로 변환하기
- 입력 상태를 보존하면서 최신 관측값을 반영한 새 상태 만들기
- 예상 결과와 실제 결과를 비교하며 구현 확인하기

| 폴더 | 용도 |
| --- | --- |
| [skeleton](skeleton/) | 학생용 코드입니다. `interface_rules.py`에 구현할 부분이 남아 있습니다. |
| [solution](solution/) | 모범 답안입니다. 직접 구현한 뒤 동작과 풀이를 비교할 수 있습니다. |

두 폴더는 각각 독립적으로 실행할 수 있으며, 다음 파일을 포함합니다.

| 파일 | 역할 |
| --- | --- |
| `app.py` | 프로그램을 실행하는 시작점 |
| `interface_rules.py` | 선택 정보, 지도 색상, 시계열 / 이벤트, 좌표, 관측값 처리 규칙 |
| `interface_support.py` | 기존 도시 연결, 자료 읽기 / 검증, JSON 저장 / 불러오기 |
| `interface_gui.py` | 지도, 선택 패널, 그래프, 관측 자료와 버튼을 표시하는 화면 |
| `checks_interface.py` | 이번 실습의 TODO별 누적 검사와 통합 검사 |
| `data/observations.csv` | 최신 / 지연 / 중복 / 누락 등을 확인하는 예제 관측 자료 |
| `data/map_example.json` | 점 / 선 / 면을 셀로 바꾸기 위한 가상 지도 자료 |

실습에서는 `skeleton/interface_rules.py`를 수정합니다. 교통 / 행위자 / 공공서비스 / 재정 등 이전 실습의 코드는 구현된 상태로 제공됩니다. `checks.py` 등은 이전 실습의 검사이며, 이번에는 **`checks_interface.py`**를 사용합니다.

## 2. 준비하고 실행하기

### 실행 환경 확인

Python **3.10 이상**과 Tkinter가 필요합니다. 실행 코드에서는 Python 표준 라이브러리만 사용하므로 별도의 `pip install`은 필요하지 않습니다. 네트워크 접속 없이 실습할 수 있습니다.

**이 문서의 모든 터미널 명령은 `README.md`, `skeleton`, `solution`이 함께 있는 폴더에서 실행합니다.**

```sh
python --version
python -m tkinter
```

두 번째 명령으로 작은 테스트 창이 열리면 닫고 다음으로 진행하세요. Windows에서 Tkinter가 없다면 Python 설치 프로그램의 Tcl/Tk 항목을 확인하세요. Linux 등에서는 운영체제의 Python용 Tk 패키지를 확인합니다.

환경에 따라 실행 명령이 `python`, `py` 또는 `python3`일 수 있습니다.

### 실습 화면 열기

```sh

```

처음에는 일부 값이 표시되지 않거나 아직 작성하지 않은 기능이 있다는 안내가 나올 수 있습니다. TODO가 남아 있기 때문에 나타나는 정상적인 안내입니다.

## 3. 인터페이스 데이터를 읽는 방법

### 선택 정보와 시계열

`feature`는 화면에서 선택한 시설이나 주거지의 정보를 담은 딕셔너리입니다.

| 값 | 의미 |
| --- | --- |
| `feature["name"]` / `feature["metric"]` | 대상 이름 / 표시할 지표 이름 |
| `feature["value"]` / `feature["unit"]` | 값 / 단위. 예: `14`와 `"명"` |
| `feature["source"]` | `"simulation"`은 모형 계산값, `"observation"`은 예제 관측값 |
| `feature`의 `missing_label` | 값이 `None`일 때 사용할 문구. 없으면 `"자료 없음"` |
| `hour` | 서비스 모형을 시작한 뒤 지난 시간. `6`이면 `"6시간째"` |
| `history`의 각 기록 | `hour`와 `queue` 같은 지표 값을 담은 딕셔너리 |
| `events`의 각 기록 | `hour`, `target_id`, `message` 등을 담은 이벤트 딕셔너리 |

**0과 None을 구분하세요.** 대기 인원 0명은 유효한 값입니다. 값이 `None`이면 결측을 표시하며, 병원 접근시간의 `None`은 `경로 없음`이라는 뜻입니다. 숫자와 단위는 `14명`, `2m³`, `6명/시간`처럼 붙여 표시하고, 숫자의 불필요한 소수점은 생략합니다.

시계열은 이미 시간순으로 전달됩니다. 기록 시각이 0 / 2 / 5 / 9시간이면 그대로 유지하세요. 목록의 순번으로 바꾸거나 빠진 시각의 자료를 만들지 않습니다. 찾는 키가 없으면 값은 `None`입니다.

### 지도 색상과 좌표

접근시간은 다음 고정 구간으로 표시합니다. **색상과 문구를 함께 반환하세요.**

| 접근시간 | `color` | `label` |
| --- | --- | --- |
| 5분 이하 | `#107C10` | `5분 이하` |
| 5분 초과~15분 이하 | `#0078D4` | `5분 초과~15분 이하` |
| 15분 초과 | `#CA5010` | `15분 초과` |
| `None` | `#767676` | `경로 없음` |

기본 지도는 가로 100m, 세로 80m이며 20m 셀의 4행 / 5열입니다. 공간 좌표의 원점은 왼쪽 아래 `(0, 0)`이고, 화면의 0행은 맨 위입니다. 좌표를 `(x, y)`로 받아 **`(행, 열)` 순서로 반환**합니다.

지도 범위는 `0 ≤ x < 100`, `0 ≤ y < 80`으로 오른쪽 / 위쪽 경계는 포함하지 않습니다. 범위 밖이면 `None`을 반환하세요. 검사에서는 다른 원점도 사용하므로 숫자를 고정하지 말고 함수 인자로 받은 원점 / 셀 크기 / 행과 열의 수를 읽으세요.

### 관측값과 상태 보존

`current`는 현재 관측 상태, `incoming`은 새로 받은 관측 자료입니다. 각각 `target_id`, `unit`, `value`, `observed_at`, `received_at`을 담고 있습니다.

- `target_id`는 대상 ID입니다. `H`는 병원, `W`는 급수 시설입니다.
- `observed_at`은 관측한 시각, `received_at`은 자료를 받은 시각입니다.
- 두 시각은 당일 0시부터 지난 분입니다. 예를 들어 `605`는 10시 5분입니다.
- 최신 여부는 **`observed_at`으로 판단**합니다. 나중에 받았어도 과거의 관측일 수 있습니다.

대상 → 단위 → 값 누락 → 관측 시각 순서로 확인하며, 먼저 발견한 거절 이유를 유지합니다. 현재 관측 시각이 `None`이면 앞의 조건을 만족하는 첫 관측을 반영합니다. 반영 여부와 관계없이 **반환 상태는 독립적인 딕셔너리**여야 합니다.

여섯 함수 모두 입력 자료를 보존합니다. 관측값은 별도 상태에 저장하며 모형의 대기 인원을 덮어쓰지 않습니다. 서비스의 경과 시간, 도시의 일수, 행위자 / 재정의 월수, 관측 시각도 각각 구분해서 읽으세요.

제공한 지도는 OSM의 node / way / tag 구조를 본뜬 가상 자료이고, CSV도 직접 만든 예제입니다. 실제 도시나 실시간 센서와 연결된 데이터가 아닙니다. 필드와 단순화 방식은 [제공 자료 안내](skeleton/data/README.md)를 참고하세요.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/interface_rules.py`에서 해당 함수와 TODO 주석을 읽습니다.
2. `pass` 자리에 코드를 작성합니다. 주석만 있는 TODO는 그 아래에 코드를 추가합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 아래 코드는 실행되지 않습니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 앱을 다시 실행해 해당 화면을 확인합니다. TODO 1과 6은 여러 부분으로 나뉘어 있으므로 각 부분을 함께 완성합니다.

| 단계 | 구현할 함수 | 이번 단계에서 할 일 | 검사 명령 |
| --- | --- | --- | --- |
| 1 | `build_selection_info` | 이름 / 지표 / 시각 / 값과 단위 / 출처를 표시할 dict 반환 | `python skeleton/checks_interface.py --stage 1` |
| 2 | `layer_style` | 접근시간에 따른 `color`, `label` dict 반환 | `python skeleton/checks_interface.py --stage 2` |
| 3 | `build_time_series` | 실제 시각과 값을 묶은 `(hour, 값)` 목록 반환 | `python skeleton/checks_interface.py --stage 3` |
| 4 | `find_events` | 같은 시각 / 대상의 이벤트 dict를 입력 순서대로 반환 | `python skeleton/checks_interface.py --stage 4` |
| 5 | `point_to_cell` | 지도 안의 점은 정수 `(행, 열)`, 지도 밖의 점은 `None` 반환 | `python skeleton/checks_interface.py --stage 5` |
| 6 | `apply_observation` | `state`, `accepted`, `reason`을 담은 dict 반환 | `python skeleton/checks_interface.py --stage 6` |

1단계의 반환 키는 `title`, `metric`, `time_label`, `value_label`, `source_label`입니다. 4단계에서 일치하는 이벤트가 없으면 빈 목록을 반환합니다. 6단계에서는 반영할 때 새 관측의 복사본을, 거절할 때 기존 상태의 복사본을 반환합니다.

`--stage 3`은 **1~3단계를 모두 검사**합니다. 단계를 생략한 `python skeleton/checks_interface.py`는 전체 6단계를 검사합니다.

작성 전 1단계를 검사하면 다음처럼 표시됩니다.

```text
[미구현] TODO 1: TODO 1: build_selection_info / interface_rules.py를 작성하세요.
1개 항목을 구현한 뒤 다시 확인하세요.
```

| 표시 | 의미와 다음 행동 |
| --- | --- |
| `[통과]` | 해당 검사에서 기대한 결과가 나왔습니다. |
| `[미구현]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]` | 결과 불일치 또는 실행 중 예외입니다. 함께 출력된 기대값 / 실제 값이나 오류 메시지를 확인하세요. |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 전체가 통과하면 `선택한 검사를 모두 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, 미구현 `2`이며, 실패와 미구현이 함께 있으면 `1`입니다.

여섯 함수를 완성하면 통합 검사를 별도로 실행하세요.

```sh
python skeleton/checks_interface.py --integration
```

통합 검사는 서비스 시간 진행, 정보 조회, 관측값 처리, 상태 저장 / 복원을 확인합니다. `--stage`와 `--integration`은 함께 사용하지 않습니다. 두 검사 모두 GUI 창 없이 실행할 수 있습니다.

### 실험 B: 좌표를 셀로 바꾸기

**공간 자료를 셀로 변환**에서 다음 좌표를 입력하고 `셀 좌표 확인`을 누르세요.

| 입력 좌표 `(x, y)` | 반환값 `(행, 열)` |
| --- | --- |
| `(45, 30)` | `(2, 2)` |
| `(0, 0)` | `(3, 0)` |
| `(99.99, 79.99)` | `(0, 4)` |
| `(100, 20)` 또는 `(20, 80)` | `None` |

`지도 자료 변환`도 실행해 보세요. 예제 병원 H의 위치 `(10, 30)`은 `(2, 0)` 셀에 표시됩니다. 건물을 한 셀로 바꾸면 원래의 모양 / 면적 / 여러 셀에 걸친 범위 중 어떤 정보가 사라지는지 설명해 보세요.

### 실험 C: 늦게 도착한 관측값

**관측 자료 확인**에서 `초기화`를 누른 뒤 `다음 관측 받기`를 여덟 번 누르세요. 처음 상태는 병원 H, 8명, 관측 시각 10:00입니다.

| CSV 행 | 확인할 상황 | `reason` | 반영 후 관측값 |
| --- | --- | --- | ---: |
| 1 | H / 10명 / 10:05 관측 | `applied` | 10명 |
| 2 | H / 14명 / 10:10 관측 | `applied` | 14명 |
| 3 | H / 12명 / 10:07 관측이 늦게 도착 | `stale` | 14명 유지 |
| 4 | 같은 10:10 관측을 다시 수신 | `duplicate` | 14명 유지 |
| 5 | 대상이 W인 자료 | `target_mismatch` | 14명 유지 |
| 6 | 단위가 리터인 자료 | `unit_mismatch` | 14명 유지 |
| 7 | 관측값 누락 | `missing` | 14명 유지 |
| 8 | H / 0명 / 10:30 관측 | `applied` | 0명 |

반영하면 `accepted`는 `True`, 거절하면 `False`입니다. 왜 받은 시각만으로 최신 자료를 판단하면 안 되는지, 마지막 0명이 누락값과 어떻게 다른지 설명해 보세요.

## 7. 막혔을 때 확인할 것

| 증상 | 확인할 내용 |
| --- | --- |
| `python` 명령을 찾지 못함 | Python 설치를 확인하고 환경에 따라 `python`, `py` 또는 `python3`로 실행합니다. |
| `can't open file` 또는 파일을 찾지 못함 | 터미널이 이 README가 있는 폴더인지 확인합니다. 이미 `skeleton` 안이라면 `python app.py`, `python checks_interface.py --stage 1`처럼 폴더 접두사를 뺍니다. |
| Tkinter를 찾지 못하거나 창이 열리지 않음 | `python -m tkinter`로 설치를 확인합니다. GUI는 화면을 표시할 수 있는 PC에서 실행해야 합니다. 검사 스크립트는 GUI 없이 실행할 수 있습니다. |
| 코드를 썼는데 계속 미구현 | 저장 여부와 해당 함수의 `raise NotImplementedError(...)` 줄을 확인합니다. |
| 화면에 수정한 내용이 반영되지 않음 | 실행 중인 창을 닫고 다시 실행합니다. `solution` 대신 `skeleton`을 실행했는지도 확인합니다. |
| 0명이 자료 없음으로 표시됨 | `if value` 대신 `value is None`으로 결측을 구분했는지 확인합니다. |
| 그래프의 시각이나 이벤트가 다름 | 실제 `hour`를 사용했는지, 이벤트 조건에 시각과 대상 ID를 모두 넣었는지 확인합니다. |
| 셀 위치가 뒤집히거나 경계 밖 점이 포함됨 | 원점 이동, `(행, 열)` 반환 순서, 화면의 행 방향, 오른쪽 / 위쪽 경계 제외를 확인합니다. |
| 오래된 관측이 반영되거나 원본까지 바뀜 | `observed_at`으로 비교했는지, 입력을 수정하거나 반환 상태와 같은 dict를 공유하지 않았는지 확인합니다. |
| 데이터 파일을 찾지 못함 | 폴더 전체를 압축 해제했는지, 각 실행 폴더의 `data/`에 CSV와 JSON이 있는지 확인합니다. |
