# 행위자 기반 도시 모델링 실습

시민 / 가구 / 기업의 행동 규칙을 구현하고, 이주와 이전이 통근 시간과 공간 분포를 어떻게 바꾸는지 관찰하는 Python 실습입니다.

**[skeleton/agent_rules.py](skeleton/agent_rules.py)의 TODO 1~7을 순서대로 완성하세요.** 각 TODO의 자세한 힌트는 코드 바로 옆 주석에 있습니다.

## 1. 실습 목표와 파일 구성

이번 실습에서는 다음을 연습합니다.

- 딕셔너리와 ID로 시민 / 가구 / 주택 / 기업 / 사업장을 연결하기
- 만족도, 비용, 대기 기간을 조건으로 행동 결정하기
- 이동할 때 양쪽 참조 관계와 보유 자금 함께 갱신하기
- 이웃 만족 기준을 바꾸고 이동 횟수와 공간 분포 비교하기
- 예상 결과와 실제 결과를 비교하며 구현 확인하기

| 폴더                  | 용도                                                               |


## 3. 행위자 데이터를 읽는 방법

### 시민과 가구 / 기업의 연결

`session`은 도시와 교통을 포함한 실험 전체 상태이며, `state = session["agents"]`는 그중 행위자 상태입니다. `move_household`와 `move_firm`에 전달되는 값은 이 `state`입니다.

| 값                    | 의미                                                                                |
| --------------------- | ----------------------------------------------------------------------------------- |
| `state["citizens"]`   | 시민 ID를 키로, 소속 가구 `household_id`와 고용 기업 `employer_id`를 저장           |
| `state["households"]` | 가구 ID를 키로, 주택 `home_id`, 가구원 `members`, 소득 / 저축 / 대기 기간 등을 저장 |
| `state["houses"]`     | 주택 ID를 키로, 임대료 `rent`, 환경 `environment`, 입주 가구 `occupant`를 저장      |
| `state["firms"]`      | 기업 ID를 키로, 사업장 `site_id`, 직원 `employees`, 이익 / 자금 / 이전 비용을 저장  |
| `state["sites"]`      | 사업장 ID를 키로, 입주 기업 `occupant`와 월 이익 `profit`을 저장                    |
| `state["month"]`      | 진행한 개월 수. 처음은 0개월이며, 행위자 모델의 1 tick은 1개월                      |

예를 들어 시민 P1의 `household_id`는 `"H1"`입니다. `state["households"]["H1"]["home_id"]`가 `"A"`이면 주택 조건은 `state["houses"]["A"]`에서 읽습니다. 고용 기업 `"F1"`의 `site_id`가 `"X"`이면 사업장 정보는 `state["sites"]["X"]`에서 읽습니다.

**참조 필드에는 딕셔너리 전체가 아니라 ID 문자열을 저장합니다.** 빈 주택 / 사업장의 `occupant`와 미취업 시민의 `employer_id`는 `None`입니다. 가구가 이주해도 시민의 소속 가구는 같고, 기업이 이전해도 직원의 고용 관계는 같습니다.

### 입력을 읽는 함수와 바꾸는 함수

`satisfaction`, `should_move`, `choose_home`, `should_move_firm`, `same_type_ratio`는 입력을 읽기만 합니다. `move_household`와 `move_firm`은 승인된 이동을 입력 상태에 직접 반영하며, 새 상태를 반환할 필요는 없습니다.

이웃 격자에는 `"A"`, `"B"`, `None`이 전달됩니다. 좌표는 `(x, y)`로 표현하지만 셀을 읽을 때는 **`grid[y][x]`** 순서입니다. 이웃 실험의 A / B는 유형이며 도시 지도에 표시된 주택 A / B와는 별개입니다.

### 만족도 계산

시간의 단위는 편도 분, 금액의 단위는 만원, 환경 점수는 0~100점입니다.

| 점수          | 계산식                                  | 예외 처리                        |
| ------------- | --------------------------------------- | -------------------------------- |
| 통근 점수 C   | `100 × max(0, 1 − commute_min / 60)`    | `commute_min`이 `None`이면 0점   |
| 주거비 점수 R | `100 × max(0, 1 − rent / income)`       | `income`이 0이면 0점             |
| 만족도 S      | `0.5 × C + 0.3 × R + 0.2 × environment` | 계산 결과를 반올림하지 않고 반환 |

예를 들어 `satisfaction(45, 80, 200, 50)`의 결과는 `40.5`입니다.

### 가구의 이주

- 이주 검토 조건은 `dissatisfied_months >= 2`, `cooldown == 0`, `savings >= move_cost`를 모두 만족하는 것입니다.
- 후보는 `home_id`, `feasible`, `score`를 가진 딕셔너리입니다. 앞의 세 후보 중 입주 가능하고 현재보다 만족도가 **10점 이상** 높은 첫 후보를 선택합니다. 후보 순서를 바꾸지 않습니다.
- 이주가 승인되면 옛 주택의 `occupant`를 `None`으로, 새 주택의 `occupant`를 가구 ID로 바꿉니다. 가구의 `home_id`를 갱신하고 이사 비용을 한 번 차감한 뒤, `dissatisfied_months`는 0, `cooldown`은 3으로 설정합니다.

제공 코드는 매월 만족도가 50점 미만이면 연속 불만족 기간을 늘리고, 50점 이상이면 0으로 초기화합니다. 입주 가능 여부와 후보 점수도 미리 계산합니다. 같은 주택에 여러 가구가 신청하면 제공 코드가 한 가구를 추첨하므로, 학생 함수에서 배정 로직을 새로 작성할 필요는 없습니다. 이주한 다음 세 달 동안은 재이주하지 않습니다.

### 기업의 이전

- 6개월 순편익은 `6 × (candidate_profit − profit) − move_cost`입니다.
- 순편익이 **0보다 크고**, `cash >= move_cost`일 때 이전할 수 있습니다.
- 이전이 승인되면 옛 사업장의 `occupant`를 비우고 새 사업장에 기업 ID를 기록합니다. 기업의 `site_id`를 갱신하고 이전 비용을 한 번 차감한 뒤, 새 사업장의 `profit`을 기업에 반영합니다.

제공 코드는 3·6·9개월처럼 분기마다 기업의 이전을 검토합니다. 가구 이주와 기업 이전 모두 시민의 소속 가구 및 고용 관계를 유지해야 합니다. 기업이 이전하면 직원의 통근 목적지가 새 사업장으로 바뀝니다.

### 이웃 비율

자신을 제외한 주변 8칸에서 격자 안에 있는 칸만 조사합니다. 값이 `None`인 빈칸은 분모에서 제외하고, 같은 유형의 이웃 수를 거주 이웃 수로 나눕니다. 격자의 반대편을 이웃으로 연결하지 않습니다.

거주 이웃이 없으면 `None`을 반환합니다. 제공 코드는 이 경우를 만족한 상태로 처리합니다. 이동 후보를 평가할 때 출발지를 비우고 후보 위치에 행위자를 놓는 처리는 이미 구현되어 있습니다.

## 4. TODO를 한 단계씩 완성하기

각 단계에서 다음 순서를 반복하세요.

1. `skeleton/agent_rules.py`에서 해당 함수의 설명과 TODO 주석을 읽습니다.
2. 주석의 안내에 따라 구현 코드를 작성합니다. 함수 이름과 매개변수는 유지합니다.
3. 그 함수의 구현을 마쳤다면 **`raise NotImplementedError(...)` 한 줄 전체를 삭제합니다.** 이 줄이 남아 있으면 함수 실행이 그 자리에서 멈춥니다.
4. 파일을 저장하고 해당 단계의 검사 명령을 실행합니다.
5. 검사를 통과하면 다음 TODO로 이동합니다. 화면으로 확인하려면 프로그램을 닫고 다시 실행합니다.

| 단계 | 구현할 함수        | 이번 단계에서 할 일                                                               | 검사 명령                                |
| ---- | ------------------ | --------------------------------------------------------------------------------- | ---------------------------------------- |
| 1    | `satisfaction`     | 통근 / 주거비 / 환경 점수의 가중합 반환                                           | `python skeleton/checks_abm.py --stage 1` |
| 2    | `should_move`      | 불만족 기간 / 대기 기간 / 이사 비용으로 이주 검토 여부 판단                       | `python skeleton/checks_abm.py --stage 2` |
| 3    | `choose_home`      | 앞의 세 후보 중 입주 가능하고 10점 이상 개선되는 첫 후보 dict 반환. 없으면 `None` | `python skeleton/checks_abm.py --stage 3` |
| 4    | `move_household`   | 주택 / 가구 참조, 저축, 불만족 기간과 대기 기간 갱신                              | `python skeleton/checks_abm.py --stage 4` |
| 5    | `should_move_firm` | 6개월 순편익과 이전 자금으로 기업 이전 여부 판단                                  | `python skeleton/checks_abm.py --stage 5` |
| 6    | `move_firm`        | 사업장 / 기업 참조, 자금과 월 이익 갱신                                           | `python skeleton/checks_abm.py --stage 6` |
| 7    | `same_type_ratio`  | 거주 이웃 중 같은 유형의 비율 반환. 거주 이웃이 없으면 `None`                     | `python skeleton/checks_abm.py --stage 7` |

`--stage 3`은 **TODO 1~3을 모두 검사**합니다. 앞 단계의 실패부터 해결하세요. 옵션을 생략하면 전체 7개 TODO를 검사하며, `--integration`은 모두 완성한 뒤 통합 동작을 확인하는 별도 명령입니다.

```sh
python skeleton/checks_abm.py
python skeleton/checks_abm.py --integration
```

기존 도시 지표의 `checks.py`도 같은 방식으로 실행합니다. `python skeleton/checks.py --stage 3`은 1~3단계, `python skeleton/checks.py`는 전체 6단계를 검사합니다.

처음 TODO 1을 검사하면 다음처럼 표시됩니다.

```text
[미완성] TODO 1: 만족도: TODO 1: 가구의 만족도 점수를 계산하세요.
```

| 표시 | 의미와 다음 행동 |
| --- | --- |
| `[통과]` | 해당 검사에서 기대한 결과가 나왔습니다. |
| `[미완성]` | 호출한 함수에 `NotImplementedError`가 남아 있습니다. 해당 TODO를 완성하세요. |
| `[실패]` | 기대값과 실제값이 다릅니다. 함께 출력된 두 값을 비교하세요. |
| `[오류]` | 실행 중 예외가 발생했습니다. 오류 메시지와 파일 / 줄 번호를 확인하세요. |

문법 오류나 들여쓰기 오류는 위 표시가 나오기 전에 실행을 중단할 수도 있습니다. 선택한 검사가 모두 통과하면 `요청한 모든 점검을 통과했습니다.`가 출력됩니다. 종료 코드는 통과 `0`, 실패 / 오류 `1`, TODO 미완성 `2`입니다. 실패 / 오류와 미완성이 함께 있으면 `1`을 반환합니다. 잘못된 명령 옵션은 argparse가 사용법과 함께 종료 코드 `2`로 알립니다. `--stage`와 `--integration`은 함께 지정하지 않습니다. 검사는 GUI 없이 실행할 수 있습니다.

**행위자의 월, 교통의 분, 이웃 모형의 회차는 각각 따로 진행됩니다.** `1개월 진행`은 교통 시간을 늘리지 않고, `1분 진행`은 가구·기업의 월을 늘리지 않습니다. 이웃 격자는 도시의 주택·기업 모형과 별개의 실험입니다. 월을 진행하면 기존 분 단위 지표 기록은 비워집니다.

### 저장과 결과 정리

- `상태 저장`은 도시·교통·행위자 상태와 기록을 JSON으로 저장합니다. `불러오기`로 복원할 수 있습니다. 행위자 상태 예제는 [abm_month6.json](skeleton/examples/abm_month6.json)입니다.
- 이웃 격자의 배치와 진행 상황은 상태 파일에 포함되지 않습니다. 불러오면 이웃 실험은 기본 기준 `0.5`로 초기화됩니다.
- `월별 CSV`는 행위자 월별 기록을 내보냅니다. 먼저 1개월 이상 진행해야 합니다.
- `CSV 내보내기`는 분 단위 도시 지표 기록을 내보냅니다.

결과를 정리할 때는 선택한 주택과 제외한 후보의 이유, 이주·이전 전후의 자금과 참조 관계, 직원의 통근 변화, 이웃 기준별 분포 차이를 기록하세요.

## 6. 결과를 비교해 보기

### 실험 A: 기본 도시

TODO를 모두 구현한 뒤 `기본 도시`를 선택하고, 지도나 교통 설정을 바꾸지 않은 상태에서 월을 진행합니다. 평균 통근 시간은 도달 가능한 취업 시민을 기준으로 계산합니다.

| 시점    | H1 주택 | H1 저축(만원) | F1 사업장 | F1 자금(만원) | 평균 통근(분) |
| ------- | ------- | ------------: | --------- | ------------: | ------------: |
| 0~1개월 | A       |           150 | X         |           700 |          30.0 |
| 2개월   | B       |           120 | X         |           700 |          17.5 |
| 3~6개월 | B       |           120 | Y         |           200 |          32.5 |

H1의 이주 후 통근 시간이 줄어드는 이유와, F1의 이전 후 평균 통근 시간이 다시 늘어나는 이유를 설명해 보세요. 자세한 기준값은 [expected_results_abm.json](skeleton/expected_results_abm.json)에 있습니다.

### 실험 B: 이웃 만족 기준 비교

1. `이웃과 도시 변화`에서 만족 기준을 `0.25`, `0.5`, `0.75` 중 하나로 선택합니다.
2. **기준을 바꾼 뒤 `초기화`를 눌러 적용합니다.** 시드 42의 같은 초기 배치에서 시작합니다.
3. `1회 진행` 또는 `10회 진행`으로 최대 30회차까지 관찰합니다. 이동이 없는 회차가 나오면 멈춥니다. `10회 진행`도 도중에 이동이 없으면 중단됩니다.
4. 최종 회차, 불만족 인원, 누적 이동 횟수, 유형별 분포를 기록하고 기준별 결과를 비교합니다.

격자는 8×8이며 A 25명, B 25명, 빈칸 14개가 유지되어야 합니다. 기본 기준 `0.5`에서는 초기 불만족 인원이 21명이고, 1회차에 15번 이동한 뒤 2명이 남습니다. 9회차에는 불만족 인원이 0명, 누적 이동은 28번이며 10회차에는 이동이 없습니다.

이동이 멈추는 것과 모두가 만족하는 것은 다른 조건입니다. 다른 기준에서도 불만족한 행위자가 남아 있는지 확인하고, 단일 시드의 결과만으로 일반화하지 않습니다.
